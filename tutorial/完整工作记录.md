### 2.1 初始构建

**生成的第一个版本包含：**

- 释义（中英双语）
- 词性标注

- 搭配（约 5 条/词）
- 例句（5 条/词，含 CET-4/6、考研、TOEFL/IELTS、Academic、Common）

### 2.2 中文翻译补充

逐步添加：
- 词源中文翻译（`**词源：**` 行）
- 所有短语的中文翻译（`— 中文`）
- 所有例句的中文翻译（`（中文翻译）`）

### 2.3 Usage Notes 翻译 + 搭配扩充

- 每条使用说明补充中文翻译
- 搭配从 ~5 条扩充到 **8-10 条/词**，新增大量介词搭配

### 2.4 目录优化

- 初始：单列列表
- 改为 **3 列 HTML 表格**
- 最终改为 **2 列 HTML 表格**，显示序号 + 可点击动词名 + 全量搭配

### 2.5 排版优化

- 添加 CSS 样式（字号、行距）
- 例句放入 `<details>` 可折叠块
- 每个动词间用 `---` 分隔

### 2.6 例句分离 EN/CN + 折叠

- **EN 例句块**：`<details open>` 默认展开
- **CN 翻译块**：`<details style="font-size: 13px !important">` 默认折叠
- EN/CN 条目一一对应

### 2.7 搭配中英文分离 + 折叠

搭配和介词模式也按中英文分离：

```
**General Collocations (English):**  ← 展开
<details>
<summary><b>General Collocations (中文)</b></summary>  ← 折叠

**Preposition Patterns (English):**  ← 展开
<details>
<summary><b>Preposition Patterns (中文)</b></summary>  ← 折叠
```

### 2.8 渲染修复

在迭代中踩过的坑：

| 问题 | 原因 | 修复 |
|------|------|------|
| `**粗体**` 显示为文字 | 在 `<summary>` 等 HTML 标签内使用 markdown | 改用 `<b>文字</b>` |
| markdown 标题不渲染 | HTML 标签后缺少空行 | 在 `</details>` 和 `**标题**` 之间加空行 |
| 中文字体不变小 | 页级 CSS `!important` 覆盖了内联样式 | 内联样式也加 `!important` |
| 文档重复/截断 | 多次编辑导致文件积累多余区块 | 清理重复的 TOC 和 Verb Details 区块 |
| 搭配条目抽取不全 | `re.findall` 未用 `re.MULTILINE` | 加上 MULTILINE 标志 |

### 2.9 最终优化

- 中文例句块默认折叠
- 中文块字体缩小到 13px
- 字体整体调大（body 18px, h1 32px, h2 26px, h3 20px）

## 三、MCP 服务安装与调试（5月13日）

### 3.1 Cambridge Dictionary MCP

目标：让 opencode AI 能直接查询 Cambridge 词典。

**安装步骤：**

```bash
npm install -g mcp-server-dictionary
```

**opencode 配置（关键）：**

```json
{
  "mcp": {
    "cambridge-dict": {
      "type": "local",
      "command": ["node.exe", "C:\\Program Files\\nodejs\\node_global\\node_modules\\mcp-server-dictionary\\build\\index.js"]
    }
  }
}
```

**踩坑记录：**

| 问题 | 原因 |
|------|------|
| `Missing property "type"` | opencode 配置需要 `"type": "local"` |
| `Property mcpServers is not allowed` | 字段名是 `"mcp"` 不是 `"mcpServers"` |
| `Value is not accepted. Valid values: "local"` | 写成了 `"stdio"`，opencode 用 `"local"` |
| `Operation timed out after 30000ms` | npx 首次启动需下载包，超时 |
| npx 管道不通 | WSL 环境中 npx → Windows Node.js 的 stdin/stdout 未正确连接 |

**最终解决方案：**
跳过 npx，直接用 `node.exe` + Windows 绝对路径。路径必须用 `C:\...` 风格（不能用 `/mnt/c/...`），因为 `node.exe` 是 Windows 程序，不认识 Linux 路径。

## 八、经验教训

### 8.1 opencode 配置要点

```
mcpServers → mcp              ← 字段名不是 mcpServers
type: "stdio" → "local"       ← 类型名不是 stdio
command: 必须是数组            ← 不能分开写 command + args
```

### 8.2 WSL + Windows 混用环境

- 跨系统调用时，文件路径、环境变量、stdin/stdout 管道都可能有兼容问题
- **哪个系统的程序，就用哪个系统的路径**：
  - Windows 程序 → `C:\...` 路径
  - WSL 调用 Windows 程序时 → 可写包装脚本或用完整路径
- npx 在 WSL 下管道 stdio 有问题 → 改用 `node.exe` 直接调用

### 8.3 Markdown 排版

- HTML 标签（`<details>`、`<summary>`）内**不能使用 markdown 语法**
- HTML 标签后接 markdown 内容，**必须空行隔开**，否则 markdown 不会被渲染
- `<details>` 折叠块内部的列表需要空行才能正确渲染

### 8.4 批量数据处理

- 148 动词 × 多个子表 = 大量重复性工作 → 使用 task agent 并行处理
- EN/CN 条目必须一一对应 → 需要在生成时严格计数
- Preposition Patterns 条目数 = 介词搭配例句数（关键一致性检查点）
