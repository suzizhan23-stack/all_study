# 第1章 简介

全世界的计算机科学课程都包含数据结构和算法（data structures and algorithms）的课程。数据结构就是如此重要；它们改善了我们的生活质量，甚至经常挽救生命。许多价值数百万乃至数十亿美元的公司都是围绕数据结构建立的。

怎么会这样呢？如果我们停下来想一想，就会发现我们不断地与数据结构进行交互。

- **打开文件：** 文件系统（file system）数据结构用于定位文件在磁盘上的各个部分，以便能够检索它们。这并不容易；磁盘包含数亿个块。你的文件内容可能存储在其中的任何一个块上。
- **在手机上查找联系人：** 使用数据结构在你的联系人列表中查找电话号码，甚至在你完成拨号/输入之前，基于部分信息就能找到。这并不容易；你的手机可能包含很多人的信息——你曾经通过电话或电子邮件联系过的所有人——而且你的手机没有非常快的处理器或大量的内存。
- **登录你最喜欢的社交网络：** 网络服务器使用你的登录信息来查找你的账户信息。这并不容易；最流行的社交网络拥有数亿活跃用户。
- **进行网络搜索：** 搜索引擎使用数据结构来查找包含你搜索词条的网页。这并不容易；互联网上有超过85亿个网页，每个页面都包含大量潜在的搜索词条。
- **拨打紧急服务电话（9-1-1）：** 紧急服务网络在你的电话号码与地址映射的数据结构中查找你的号码，以便警察、救护车或消防车能够毫不延误地赶到现场。这很重要；打电话的人可能无法提供他们所在的确切地址，而延误可能意味着生与死的差别。

## 1.1 对效率的需求 (The Need for Efficiency)

在下一节中，我们将介绍最常用的数据结构所支持的操作。任何有一点编程经验的人都会发现，正确地实现这些操作并不难。我们可以将数据存储在数组（array）或链表（linked list）中，每个操作都可以通过遍历数组或链表的所有元素，可能还会添加或删除一个元素来实现。

这种实现方式很简单，但效率不高。这真的重要吗？计算机正变得越来越快。也许这种显而易见的实现方式就足够好了。让我们做一些粗略的计算来找出答案。

#### 操作数量：

设想一个具有中等规模数据集的应用程序，比如一百万个（$10^6$）数据项。在大多数应用中，可以合理地假设该应用会至少查找每个数据项一次。这意味着我们预计至少要对这些数据进行一百万次（$10^6$）搜索。如果每次搜索都检查所有 $10^6$ 个数据项，那么总共需要 $10^6 \times 10^6 = 10^{12}$（一万亿）次检查。

#### 处理器速度：

在撰写本文时，即使是非常快的台式计算机每秒也只能执行不超过十亿（$10^9$）次操作。[^1.1] 这意味着此应用程序将至少需要 $10^{12}/10^9 = 1000$ 秒，大约16分钟40秒。16分钟在计算机时间中是极其漫长的，但一个人可能愿意忍受（如果他去喝杯咖啡休息一下的话）。

#### 更大的数据集：

现在考虑像谷歌这样的公司，它索引了超过85亿个网页。根据我们的计算，对此数据进行任何类型的查询至少需要8.5秒。我们已经知道事实并非如此；网络搜索在远小于8.5秒的时间内完成，而且它们执行的查询比仅仅询问某个页面是否在索引页面列表中要复杂得多。在撰写本文时，谷歌每秒接收大约4,500次查询，这意味着他们至少需要 $4,500 \times 8.5 = 38,250$ 台非常快的服务器才能跟上。

#### 解决方案：

这些例子告诉我们，当数据结构中的数据项数量 $n$ 和对数据结构执行的操作数量 $m$ 都很大时，数据结构的简单实现无法很好地扩展。在这些情况下，时间（以机器指令衡量）大约是 $n \times m$。

当然，解决方案是仔细组织数据结构内部的数据，使得不是每个操作都需要检查每个数据项。虽然乍听起来不可能，但我们将看到某些数据结构中，平均只需查看两个数据项就能完成一次搜索，而与数据结构中存储的数据项数量无关。在我们每秒十亿条指令的计算机上，在一个包含十亿（或万亿、千万亿甚至百万亿）个数据项的数据结构中进行搜索只需 $0.000000002$ 秒。

我们还将看到一些数据结构的实现，它们保持数据项的有序状态，在操作过程中检查的数据项数量随着数据结构中数据项数量的增长而非常缓慢地增长。例如，我们可以在任何操作中最多检查60个数据项的情况下，维护一个包含十亿个数据项的有序集合。在我们每秒十亿条指令的计算机上，这些操作每次只需 $0.00000006$ 秒。

本章的其余部分简要回顾了本书后续使用的一些主要概念。第1.2节描述了本书中所有数据结构实现的接口（interfaces），应视为必读内容。其余各节讨论：

- 一些数学回顾，包括指数、对数、阶乘、渐近（大O）记号、概率和随机化；
- 计算模型（model of computation）；
- 正确性、运行时间和空间；
- 其余章节的概述；以及
- 示例代码和排版约定。

没有这方面背景知识的读者可以暂时跳过这些内容，必要时再回来阅读。

## 1.2 接口 (Interfaces)

在讨论数据结构时，理解数据结构接口（interface）与其实现（implementation）之间的区别非常重要。接口描述数据结构做什么，而实现描述数据结构如何做。

**接口**（interface），有时也称为**抽象数据类型**（abstract data type，ADT），定义了数据结构支持的操作集以及这些操作的语义或含义。接口没有告诉我们数据结构如何实现这些操作；它只提供所支持的操作列表，以及每个操作接受的参数类型和返回值规格。

另一方面，数据结构的**实现**（implementation）包括数据结构的内部表示以及实现数据结构所支持操作的算法定义。因此，一个接口可以有多种实现。例如，在第2章中，我们将看到使用数组实现的List接口，在第3章中，我们将看到使用基于指针的数据结构实现的List接口。它们都实现了相同的接口——List——但方式不同。

### 1.2.1 队列、栈和双端队列接口 (The Queue, Stack, and Deque Interfaces)

**队列**（Queue）接口表示一个元素集合，我们可以向其中添加元素并移除下一个元素。更准确地说，Queue接口支持以下操作：

- $\mathrm{add}(x)$：将值 $x$ 添加到Queue中
- $\mathrm{remove}()$：从Queue中移除下一个（先前添加的）值 $y$ 并返回 $y$

请注意 $\mathrm{remove}()$ 操作不接受任何参数。Queue的**排队规则**（queueing discipline）决定应移除哪个元素。有许多可能的排队规则，其中最常见的包括FIFO、优先级和LIFO。

**FIFO（先进先出）队列**（FIFO Queue），如图1.1所示，按照元素添加的顺序移除它们，就像在杂货店收银台结账时排队一样。这是最常见的Queue类型，因此通常省略FIFO这个限定词。在其他教材中，FIFO Queue上的 $\mathrm{add}(x)$ 和 $\mathrm{remove}()$ 操作通常分别称为 $\mathrm{enqueue}(x)$ 和 $\mathrm{dequeue}()$。

**图1.1：** 一个FIFO队列。

![FIFO Queue](https://opendatastructures.org/ods-python/img67.png)

**优先级队列**（priority Queue），如图1.2所示，总是从Queue中移除最小的元素，相同优先级时任意选择。这类似于医院急诊室对患者进行分类的方式。患者到达后进行评估，然后被安置在候诊室。当医生有空时，他或她会首先治疗病情最危及生命的患者。在其他教材中，优先级Queue上的 $\mathrm{remove}()$ 操作通常称为 $\mathrm{delete\_min}()$。

**图1.2：** 一个优先级队列。

![Priority Queue](https://opendatastructures.org/ods-python/img70.png)

一种非常常见的排队规则是**LIFO（后进先出）**（LIFO Queue）规则，如图1.3所示。在LIFO Queue中，最近添加的元素是下一个被移除的元素。这最好用一叠盘子来形象化；盘子放在叠的顶部，也从叠的顶部取走。这种结构非常常见，以至于它有自己的名字：**栈**（Stack）。通常，在讨论Stack时，$\mathrm{add}(x)$ 和 $\mathrm{remove}()$ 的名称会改为 $\mathrm{push}(x)$ 和 $\mathrm{pop}()$；这是为了避免混淆LIFO和FIFO排队规则。

**图1.3：** 一个栈。

![Stack](https://opendatastructures.org/ods-python/img75.png)

**双端队列**（Deque）是FIFO Queue和LIFO Queue（Stack）的推广。Deque表示一个元素序列，有前端（front）和后端（back）。元素可以在序列的前端或后端添加。Deque操作的名称不言自明：$\mathrm{add\_first}(x)$、$\mathrm{remove\_first}()$、$\mathrm{add\_last}(x)$ 和 $\mathrm{remove\_last}()$。值得注意的是，Stack可以仅使用 $\mathrm{add\_first}(x)$ 和 $\mathrm{remove\_first}()$ 实现，而FIFO Queue可以使用 $\mathrm{add\_last}(x)$ 和 $\mathrm{remove\_first}()$ 实现。

### 1.2.2 列表接口：线性序列 (The List Interface: Linear Sequences)

本书将很少讨论FIFO Queue、Stack或Deque接口。这是因为这些接口被**列表**（List）接口所包含。List，如图1.4所示，表示一个值序列 $x_0,\ldots,x_{n-1}$。List接口包括以下操作：

1. $\mathrm{size}()$：返回列表的长度 $n$
2. $\mathrm{get}(i)$：返回值 $x_i$
3. $\mathrm{set}(i,x)$：将 $x_i$ 的值设置为 $x$
4. $\mathrm{add}(i,x)$：在位置 $i$ 添加 $x$，将 $x_i,\ldots,x_{n-1}$ 向后移动；
   设置 $x_{j+1}=x_j$，对于所有 $j\in\{n-1,\ldots,i\}$，增加 $n$，并设置 $x_i=x$
5. $\mathrm{remove}(i)$：移除值 $x_i$，将 $x_{i+1},\ldots,x_{n-1}$ 向前移动；
   设置 $x_j=x_{j+1}$，对于所有 $j\in\{i,\ldots,n-2\}$，并减少 $n$

注意，这些操作很容易足以实现Deque接口：

$$
\begin{aligned}
\mathrm{add\_first}(x) &\Rightarrow \mathrm{add}(0,x) \\
\mathrm{remove\_first}() &\Rightarrow \mathrm{remove}(0) \\
\mathrm{add\_last}(x) &\Rightarrow \mathrm{add}(\mathrm{size}(),x) \\
\mathrm{remove\_last}() &\Rightarrow \mathrm{remove}(\mathrm{size}()-1)
\end{aligned}
$$

**图1.4：** 一个List表示一个按 $0,1,2,\ldots,n-1$ 索引的序列。在这个List中，调用 $\mathrm{get}(2)$ 将返回值 $c$。

![List](https://opendatastructures.org/ods-python/img118.png)

虽然在后续章节中我们通常不会讨论Stack、Deque和FIFO Queue接口，但Stack和Deque这两个术语有时会用于实现List接口的数据结构名称中。当这种情况发生时，它强调这些数据结构可以非常高效地实现Stack或Deque接口。例如，ArrayDeque类是List接口的一个实现，它能够在每次操作的常数时间内实现所有Deque操作。

### 1.2.3 USet接口：无序集合 (The USet Interface: Unordered Sets)

**USet**（Unordered Set，无序集合）接口表示一个唯一元素的无序集合，模拟数学上的**集合**（set）。USet包含 $n$ 个**互不相同**（distinct）的元素；没有元素出现超过一次；元素没有特定顺序。USet支持以下操作：

1. $\mathrm{size}()$：返回集合中元素的数量 $n$
2. $\mathrm{add}(x)$：向集合中添加元素 $x$（如果尚不存在）；
   前提是集合中没有元素 $y$ 满足 $x$ 等于 $y$，则将 $x$ 添加到集合中。如果 $x$ 被添加到集合中则返回 $\mathrm{true}$，否则返回 $\mathrm{false}$。
3. $\mathrm{remove}(x)$：从集合中移除 $x$；
   在集合中查找元素 $y$ 使得 $x$ 等于 $y$，并移除 $y$。返回 $y$，如果不存在这样的元素则返回 $\mathrm{nil}$。
4. $\mathrm{find}(x)$：在集合中查找 $x$（如果存在）；
   在集合中查找元素 $y$ 使得 $y$ 等于 $x$。返回 $y$，如果不存在这样的元素则返回 $\mathrm{nil}$。

这些定义在区分 $x$（我们要移除或查找的元素）和 $y$（我们可能移除或找到的元素）时有点繁琐。这是因为 $x$ 和 $y$ 实际上是不同的对象，但被视为相等。

这种区分很有用，因为它允许创建**字典**（dictionary）或**映射**（map），将键（key）映射到值（value）。要创建字典/映射，可以构造称为**对**（Pair）的复合对象，每个Pair包含一个**键**（key）和一个**值**（value）。如果两个Pair的键相等，则它们被视为相等。如果我们在USet中存储某个对 $(k,v)$，然后稍后使用对 $x=(k,\mathrm{nil})$ 调用 $\mathrm{find}(x)$ 方法，结果将是 $y=(k,v)$。换句话说，只需要键 $k$ 就能恢复值 $v$。

### 1.2.4 SSet接口：有序集合 (The SSet Interface: Sorted Sets)

**SSet**（Sorted Set，有序集合）接口表示一个有序的元素集合。SSet存储来自某个全序关系（total order）的元素，因此任意两个元素 $x$ 和 $y$ 可以进行比较。在代码示例中，这将通过一个称为 $\mathrm{compare}(x,y)$ 的方法来完成，其中：

$$
\mathrm{compare}(x,y)
      \begin{cases}
        {}<0 & \text{如果 } x < y \\
        {}>0 & \text{如果 } x > y \\
        {}=0 & \text{如果 } x = y
      \end{cases}
$$

SSet支持 $\mathrm{size}()$、$\mathrm{add}(x)$ 和 $\mathrm{remove}(x)$ 方法，其语义与USet接口完全相同。USet和SSet之间的区别在于 $\mathrm{find}(x)$ 方法：

1. $\mathrm{find}(x)$：在有序集合中定位 $x$；
   查找集合中最小的元素 $y$，使得 $y \ge x$。返回 $y$，如果不存在这样的元素则返回 $\mathrm{nil}$。

这种 $\mathrm{find}(x)$ 操作有时称为**后继查找**（successor search）。它与 $\mathrm{USet}.\mathrm{find}(x)$ 有着根本的不同，因为即使集合中没有等于 $x$ 的元素，它也会返回有意义的结果。

USet和SSet的 $\mathrm{find}(x)$ 操作之间的区别非常重要，并且经常被忽视。SSet提供的额外功能通常是有代价的，包括更长的运行时间和更高的实现复杂度。例如，本书中讨论的大多数SSet实现的 $\mathrm{find}(x)$ 操作的运行时间与集合的大小成对数关系。另一方面，在第5章中将讨论的作为ChainedHashTable实现的USet，其 $\mathrm{find}(x)$ 操作在常数期望时间内运行。在选择使用哪种结构时，除非确实需要SSet提供的额外功能，否则应始终使用USet。

### 1.3.1 指数和对数 (Exponentials and Logarithms)

表达式 $b^x$ 表示将 $b$ 的 $x$ 次幂。如果 $x$ 是一个正整数，那么这就是 $b$ 自乘 $x-1$ 次的值：

$$
b^x = \underbrace{b\times b\times \cdots \times b}_{x}
$$

当 $x$ 是负整数时，$b^x=1/b^{-x}$。当 $x=0$ 时，$b^x=1$。当 $b$ 不是整数时，我们仍然可以通过指数函数 $e^x$（见下文）来定义指数运算，而指数函数本身又是通过指数级数定义的，但这最好留给微积分教材去讨论。

在本书中，表达式 $\log_b k$ 表示以 $b$ 为底 $k$ 的**对数**（base-$b$ logarithm）。即，满足下式的唯一值 $x$：

$$
b^{x} = k
$$

本书中的大多数对数都是以2为底的（**二进制对数**，binary logarithms）。对于这些对数，我们省略底数，所以 $\log k$ 是 $\log_2 k$ 的简写。

一种非正式但有帮助的理解对数的方式是，将 $\log_b k$ 视为将 $k$ 除以 $b$ 直到结果小于或等于1所需的次数。例如，当进行二分查找（binary search）时，每次比较将可能答案的数量减少一半。重复这个过程直到最多只有一个可能的答案。因此，当最初最多有 $n+1$ 个可能的答案时，二分查找进行的比较次数最多为 $\lceil\log_2(n+1)\rceil$。

本书中还会出现另一种对数，即**自然对数**（natural logarithm）。这里我们使用符号 $\ln k$ 表示 $\log_e k$，其中 $e$——**欧拉常数**（Euler's constant）——定义为：

$$
e = \lim_{n\rightarrow\infty} \left(1+\frac{1}{n}\right)^n \approx 2.71828
$$

自然对数经常出现，因为它是一个特别常见的积分的值：

$$
\int_{1}^{k} 1/x\,\mathrm{d}x = \ln k
$$

我们对对数进行的两个最常见的操作是将其从指数中移除：

$$
b^{\log_b k} = k
$$

以及改变对数的底数：

$$
\log_b k = \frac{\log_a k}{\log_a b}
$$

例如，我们可以使用这两个操作来比较自然对数和二进制对数：

$$
\ln k = \frac{\log k}{\log e} = \frac{\log k}{(\ln e)/(\ln 2)} = (\ln 2)(\log k) \approx 0.693147\log k
$$

### 1.3.2 阶乘 (Factorials)

在本书的一两个地方，使用了**阶乘**（factorial）函数。对于非负整数 $n$，符号 $n!$（读作"$n$ 的阶乘"）定义为：

$$
n! = 1\cdot2\cdot3\cdot\cdots\cdot n
$$

阶乘出现是因为 $n!$ 计算 $n$ 个不同元素的**排列**（permutation）数量，即不同的顺序。对于特殊情况 $n=0$，$0!$ 定义为1。

$n!$ 可以使用**斯特林近似**（Stirling's Approximation）来近似：

$$
n! = \sqrt{2\pi n}\left(\frac{n}{e}\right)^{n}e^{\alpha(n)}
$$

其中：

$$
\frac{1}{12n+1} < \alpha(n) < \frac{1}{12n}
$$

斯特林近似也近似 $\ln(n!)$：

$$
\ln(n!) = n\ln n - n + \frac{1}{2}\ln(2\pi n) + \alpha(n)
$$

（实际上，斯特林近似最容易通过将 $\ln(n!)=\ln 1 + \ln 2 + \cdots + \ln n$ 近似为积分 $\int_1^n \ln n\,\mathrm{d}n = n\ln n - n +1$ 来证明。）

与阶乘函数相关的是**二项式系数**（binomial coefficients）。对于非负整数 $n$ 和整数 $k\in\{0,\ldots,n\}$，符号 $\binom{n}{k}$ 表示：

$$
\binom{n}{k} = \frac{n!}{k!(n-k)!}
$$

二项式系数 $\binom{n}{k}$（读作"$n$ 选 $k$"）计算一个 $n$ 元素集合中大小为 $k$ 的子集的数量，即从集合 $\{1,\ldots,n\}$ 中选择 $k$ 个不同整数的方式数。

### 1.3.3 渐近记号 (Asymptotic Notation)

在本书中分析数据结构时，我们需要讨论各种操作的运行时间。确切的运行时间当然会因计算机而异，甚至在同一台计算机上因运行而异。当我们谈论操作的运行时间时，指的是操作期间执行的计算机指令数量。即使是简单的代码，这个数量也很难精确计算。因此，我们将使用所谓的**大O记号**（big-Oh notation）来替代精确的运行时间分析：对于函数 $f(n)$，$O(f(n))$ 表示一组函数：

$$
O(f(n)) = \left\{
     \begin{array}{l}
       g(n):\text{存在 $c>0$ 和 $n_0$，使得} \\
             \quad \text{$g(n) \le c\cdot f(n)$ 对所有 $n\ge n_0$ 成立}
     \end{array} \right\}
$$

从图形上看，这组函数包括那些当 $n$ 足够大时，$c\cdot f(n)$ 开始支配 $g(n)$ 的函数 $g(n)$。

我们通常使用渐近记号来简化函数。例如，对于 $5n\log n + 8n - 200$，我们可以写成 $O(n\log n)$。证明如下：

$$
\begin{aligned}
5n\log n + 8n - 200 &\le 5n\log n + 8n \\
&\le 5n\log n + 8n\log n \quad \text{当 $n\ge 2$（使得 $\log n \ge 1$）} \\
&\le 13n\log n
\end{aligned}
$$

这表明函数 $f(n)=5n\log n + 8n - 200$ 在集合 $O(n\log n)$ 中，使用了常数 $c=13$ 和 $n_0 = 2$。

使用渐近记号时，可以应用许多有用的简化规则。首先：

$$
O(n^{c_1}) \subset O(n^{c_2})
$$

对于任意 $c_1 < c_2$。其次：对于任意常数 $a,b,c > 0$，

$$
O(a) \subset O(\log n) \subset O(n^{b}) \subset O({c}^n)
$$

这些包含关系可以乘以任何正值，并且仍然成立。例如，乘以 $n$ 得到：

$$
O(n) \subset O(n\log n) \subset O(n^{1+b}) \subset O(n{c}^n)
$$

延续一个悠久而著名的传统，我们会滥用这个记号，写出像 $f_1(n) = O(f(n))$ 这样的表达式，而实际上我们的意思是 $f_1(n) \in O(f(n))$。我们还会说"这个操作的运行时间是 $O(f(n))$"，而这句话应该是"这个操作的运行时间是 $O(f(n))$ 的**一个成员**"。这些简写主要是为了避免拗口的语言，并使在等式串中使用渐近记号更加容易。

这种写法的一个特别奇怪的例子出现在我们写出像这样的语句：

$$
T(n) = 2\log n + O(1)
$$

同样，更正确的写法是：

$$
T(n) \le 2\log n + [\text{$O(1)$ 的某个成员}]
$$

表达式 $O(1)$ 还带来了另一个问题。由于这个表达式中没有变量，可能不清楚哪个变量在变得任意大。如果没有上下文，就无法判断。在上面的例子中，由于等式其余部分唯一的变量是 $n$，我们可以假设这应该理解为 $T(n) = 2\log n + O(f(n))$，其中 $f(n) = 1$。

大O记号对计算机科学来说既不是新的也不是独有的。它早在1894年就被数论学家保罗·巴赫曼（Paul Bachmann）使用，并且对于描述计算机算法的运行时间非常有用。考虑以下代码片段：执行此方法一次涉及：

- 1 次赋值（$\mathit{int}\, \mathit{i}\, \gets \, \mathit{0}$）
- $n+1$ 次比较（$\mathit{i} < \mathit{n}$）
- $n$ 次增量（$i++$）
- $n$ 次数组偏移计算（$\mathit{a}[\mathit{i}]$）
- $n$ 次间接赋值（$\mathit{a}[i] \gets i$）

所以我们可以将运行时间写为：

$$
T(n)=a + b(n+1) + cn + dn + en
$$

其中 $a$、$b$、$c$、$d$ 和 $e$ 是依赖于运行代码的机器的常数，分别表示执行赋值、比较、增量操作、数组偏移计算和间接赋值所需的时间。然而，如果这个表达式代表两行代码的运行时间，那么显然这种分析对于复杂代码或算法是不可行的。使用大O记号，运行时间可以简化为：

$$
T(n)= O(n)
$$

这不仅更加简洁，而且提供了几乎同样多的信息。在上面的例子中，运行时间依赖于常数 $a$、$b$、$c$、$d$ 和 $e$ 这一事实意味着，一般来说，不知道这些常数的值就不可能比较两个运行时间以知道哪个更快。即使我们努力确定这些常数（比如通过计时测试），我们的结论也仅对我们运行测试的机器有效。

大O记号使我们能够在更高的层次上推理，从而可以分析更复杂的函数。如果两个算法具有相同的大O运行时间，那么我们就不知道哪个更快，而且可能没有明确的胜者。一个算法可能在一台机器上更快，而另一个可能在另一台机器上更快。然而，如果两个算法具有明显不同的大O运行时间，那么我们可以确信，对于足够大的 $n$ 值，运行时间较小的那个算法会更快。

大O记号如何允许我们比较两个不同函数的一个例子如图1.5所示，该图比较了 $f_1(n)=15n$ 与 $f_2(n)=2n\log n$ 的增长速度。$f_1(n)$ 可能是一个复杂的线性时间算法的运行时间，而 $f_2(n)$ 可能是一个基于分治范式的相当简单的算法的运行时间。这说明，尽管对于小的 $n$ 值 $f_1(n)$ 大于 $f_2(n)$，但对于大的 $n$ 值情况正好相反。最终 $f_1(n)$ 以越来越大的优势胜出。使用大O记号的分析告诉我们这将会发生，因为 $O(n) \subset O(n\log n)$。

在少数情况下，我们会在具有多个变量的函数上使用渐近记号。似乎没有这方面的标准，但出于我们的目的，以下定义就足够了：

$$
O(f(n_1,\ldots,n_k)) =
   \left\{\begin{array}{@{}l@{}}
             g(n_1,\ldots,n_k):\text{存在 $c>0$ 和 $z$，使得} \\
             \quad \text{$g(n_1,\ldots,n_k) \le c\cdot f(n_1,\ldots,n_k)$} \\
             \qquad \text{对所有满足 $g(n_1,\ldots,n_k)\ge z$ 的 $n_1,\ldots,n_k$ 成立}
   \end{array}\right\}
$$

这个定义抓住了我们真正关心的情况：当参数 $n_1,\ldots,n_k$ 使 $g$ 取较大值时。当 $f(n)$ 是 $n$ 的递增函数时，这个定义也与 $O(f(n))$ 的单变量定义一致。需要提醒读者的是，尽管这对我们的目的有效，但其他教材可能对多变量函数和渐近记号有不同的处理方式。

### 1.3.4 随机化和概率 (Randomization and Probability)

本书中介绍的一些数据结构是**随机化**（randomized）的；它们做出与存储的数据或执行的操作无关的随机选择。因此，使用这些结构多次执行相同的操作集可能导致不同的运行时间。在分析这些数据结构时，我们关心的是它们的平均或**期望**（expected）运行时间。

形式上，随机化数据结构的运行时间是一个随机变量（random variable），我们希望研究它的**期望值**（expected value）。对于一个在某个可数论域 $U$ 中取值的离散随机变量 $X$，$X$ 的期望值记作 $\mathrm{E}[X]$，由以下公式给出：

$$
\mathrm{E}[X] = \sum_{x\in U} x\cdot\Pr\{X=x\}
$$

这里 $\Pr\{\mathcal{E}\}$ 表示事件 $\mathcal{E}$ 发生的概率。在本书的所有例子中，这些概率仅与随机化数据结构所做的随机选择有关；没有假设存储在结构中的数据或对数据结构执行的操作序列是随机的。

期望值最重要的性质之一是**期望的线性性**（linearity of expectation）。对于任意两个随机变量 $X$ 和 $Y$：

$$
\mathrm{E}[X+Y] = \mathrm{E}[X] + \mathrm{E}[Y]
$$

更一般地，对于任意随机变量 $X_1,\ldots,X_k$：

$$
\mathrm{E}\left[\sum_{i=1}^k X_k\right] = \sum_{i=1}^k \mathrm{E}[X_i]
$$

期望的线性性允许我们将复杂的随机变量（如上述等式的左侧）分解为简单随机变量（右侧）的和。

一个我们将反复使用的有用技巧是定义**指示器随机变量**（indicator random variables）。这些二元变量在我们想要计数时很有用，最好通过一个例子来说明。假设我们抛一枚均匀硬币 $k$ 次，想知道硬币正面朝上的期望次数。直观上，我们知道答案是 $k/2$，但如果我们尝试使用期望值的定义来证明，我们会得到：

$$
\begin{aligned}
\mathrm{E}[X] &= \sum_{i=0}^k i\cdot\Pr\{X=i\} \\
&= \sum_{i=0}^k i\cdot\binom{k}{i}/2^k \\
&= k\cdot \sum_{i=0}^{k-1}\binom{k-1}{i}/2^k \\
&= k/2
\end{aligned}
$$

这要求我们足够了解如何计算 $\Pr\{X=i\} = \binom{k}{i}/2^k$，并且知道二项式恒等式 $i\binom{k}{i}=k\binom{k-1}{i}$ 和 $\sum_{i=0}^{k} \binom{k}{i} = 2^{k}$。

使用指示器变量和期望的线性性使事情变得容易得多。对于每个 $i\in\{1,\ldots,k\}$，定义指示器随机变量：

$$
I_i = \begin{cases}
           1 & \text{如果第 $i$ 次抛硬币是正面} \\
           0 & \text{否则}
          \end{cases}
$$

那么：

$$
\mathrm{E}[I_i] = (1/2)1 + (1/2)0 = 1/2
$$

现在，$X=\sum_{i=1}^k I_i$，所以：

$$
\begin{aligned}
\mathrm{E}[X] &= \mathrm{E}\left[\sum_{i=1}^k I_i\right] \\
&= \sum_{i=1}^k \mathrm{E}[I_i] \\
&= \sum_{i=1}^k 1/2 \\
&= k/2
\end{aligned}
$$

这虽然稍微冗长一些，但不需要我们知道任何神奇的恒等式或计算任何非平凡的概率。更妙的是，它与我们的直觉一致：我们期望一半的硬币是正面朝上，正是因为每个单独的硬币以 $1/2$ 的概率正面朝上。

## 1.4 计算模型 (The Model of Computation)

在本书中，我们将分析所研究的数据结构操作的理论运行时间。为了精确地做到这一点，我们需要一个数学模型来计算。为此，我们使用**$w$ 位字RAM模型**（$w$-bit word-RAM）。RAM代表随机存取机（Random Access Machine）。在这个模型中，我们可以访问一个由**单元**（cells）组成的随机存取存储器，每个单元存储一个 $w$ 位的**字**（word）。这意味着一个内存单元可以表示，例如，集合 $\{0,\ldots,2^{w}-1\}$ 中的任何整数。

在字RAM模型中，对字的基本操作需要常数时间。这包括算术运算（$+$、$-$、$\cdot$、$/$、$\bmod$）、比较运算（$<$、$>$、$=$、$\le$、$\ge$）和按位布尔运算（按位与AND、按位或OR和按位异或XOR）。

任何单元都可以在常数时间内读取或写入。计算机的内存由内存管理系统管理，我们可以从中分配或释放任意大小的内存块。分配大小为 $k$ 的内存块需要 $O(k)$ 时间，并返回一个对新分配内存块的引用（指针）。这个引用足够小，可以用一个字来表示。

字大小 $w$ 是这个模型中非常重要的参数。我们对 $w$ 唯一做出的假设是下界 $w \ge \log n$，其中 $n$ 是任何数据结构中存储的元素数量。这是一个相当适中的假设，因为否则一个字甚至不足以计数数据结构中存储的元素数量。

空间以字为单位进行测量，因此当我们谈论数据结构使用的空间量时，指的是该结构使用的内存字数。我们所有的数据结构都存储泛型类型 T 的值，我们假设类型 T 的一个元素占用一个字的内存。

本书中介绍的数据结构不使用任何无法在标准编程语言中实现的特殊技巧。

## 1.5 正确性、时间复杂度和空间复杂度 (Correctness, Time Complexity, and Space Complexity)

在研究数据结构的性能时，有三个最重要的方面：

**正确性（Correctness）：** 数据结构应正确实现其接口。

**时间复杂度（Time complexity）：** 数据结构操作的运行时间应尽可能小。

**空间复杂度（Space complexity）：** 数据结构应使用尽可能少的内存。

在这本入门教材中，我们将正确性视为理所当然；我们不会考虑对查询给出错误答案或不正确执行更新的数据结构。然而，我们将看到一些数据结构会额外努力将空间使用降到最低。这通常不会影响操作的（渐近）运行时间，但可能会使数据结构在实践中稍慢一些。

在研究数据结构背景下的运行时间时，我们往往会遇到三种不同的运行时间保证：

**最坏情况运行时间（Worst-case running times）：** 这是最强类型的运行时间保证。如果数据结构操作的最坏情况运行时间为 $f(n)$，那么这些操作中的任何一个**从不**花费超过 $f(n)$ 的时间。

**分摊运行时间（Amortized running times）：** 如果我们说数据结构中操作的分摊运行时间为 $f(n)$，这意味着典型操作的成本最多为 $f(n)$。更准确地说，如果数据结构的分摊运行时间为 $f(n)$，那么 $m$ 个操作的序列最多需要 $mf(n)$ 的时间。某些单个操作可能需要超过 $f(n)$ 的时间，但在整个操作序列中，平均最多为 $f(n)$。

**期望运行时间（Expected running times）：** 如果我们说数据结构上操作的期望运行时间为 $f(n)$，这意味着实际运行时间是一个随机变量（见第1.3.4节），并且这个随机变量的期望值最多为 $f(n)$。这里的随机化是关于数据结构所做的随机选择。

为了理解最坏情况、分摊和期望运行时间之间的区别，考虑一个财务例子会有所帮助。考虑买房的成本：

#### 最坏情况与分摊成本：

假设一所房子售价12万美元。为了购买这所房子，我们可以获得120个月（10年）的按揭贷款，每月还款1200美元。在这种情况下，偿还这笔按揭贷款的月最坏情况成本是每月1200美元。

如果我们手头有足够的现金，我们可能会选择一次性支付12万美元买下这所房子。在这种情况下，在10年的期限内，购买这所房子的月分摊成本是：

$$
\$120,000 / 120\text{ 个月} = \$1,000\text{ 每月}
$$

这比我们如果申请按揭贷款必须支付的每月1200美元要少得多。

#### 最坏情况与期望成本：

接下来，考虑为我们的12万美元房屋购买火灾保险的问题。通过研究数十万个案例，保险公司已经确定，像我们这样的房屋遭受火灾损失的期望金额是每月10美元。这是一个非常小的数字，因为大多数房屋从未发生过火灾，少数房屋可能发生一些造成轻微烟雾损害的小火灾，而极少数的房屋会被完全烧毁。基于这些信息，保险公司每月收取15美元的火灾保险费。

现在是做决定的时候了。我们是应该支付每月15美元的火灾保险最坏情况成本，还是应该赌一把，以每月10美元的期望成本进行自我保险？显然，每月10美元**在期望上**成本更低，但我们必须能够接受**实际成本**可能高得多的可能性。在整栋房屋被烧毁的不太可能的事件中，实际成本将是12万美元。

这些财务例子也提供了关于为什么我们有时会满足于分摊或期望运行时间而不是最坏情况运行时间的见解。通常可以获得比最坏情况运行时间更低的期望或分摊运行时间。至少，如果愿意接受分摊或期望运行时间，通常可以获得一个简单得多的数据结构。

## 1.6 代码示例 (Code Samples)

本书中的代码示例是用**伪代码**（pseudocode）编写的。对于过去40年中最常见编程语言有任何编程经验的人来说，这些代码应该足够容易阅读。为了让大家了解本书中伪代码的样貌，下面是一个计算数组 $a$ 平均值的函数：

```
average(a)
    s ← 0
    for i ← 0, 1, 2, ..., length(a) - 1 do
        s ← s + a[i]
    return s / length(a)
```

这段代码所示，变量赋值使用 $\gets$ 符号。我们约定数组 $a$ 的长度用 $\mathrm{length}(a)$ 表示，数组索引从0开始，因此 $0,1,2,\ldots,\mathrm{length}(a)-1$ 是 $a$ 的有效索引。为了缩短代码，有时也为了便于阅读，我们的伪代码允许（子）数组赋值。以下两个函数是等价的：

```
left_shift(a)                         left_shift(a)
    a[0, 1, ..., length(a)-2] ←           for i ← 0, 1, 2, ..., length(a)-2 do
            a[1, 2, ..., length(a)-1]          a[i] ← a[i+1]
    a[length(a)-1] ← nil                   a[length(a)-1] ← nil
```

以下代码将数组中的所有值设置为零：

```
zero(a)
    a[0, 1, ..., length(a)-1] ← 0
```

在分析此类代码的运行时间时，我们必须小心；像 $a[0,1,\ldots,\mathrm{length}(a)-1] \gets 1$ 或 $a[1,2,\ldots,\mathrm{length}(a)-1] \gets a[0,1,\ldots,\mathrm{length}(a)-2]$ 这样的语句不是在常数时间内运行的。它们需要 $O(\mathrm{length}(a))$ 的时间。

我们对变量赋值也采用类似的简写方式，因此代码 $x,y \gets 0,1$ 将 $x$ 设置为0，$y$ 设置为1，而代码 $x,y \gets y,x$ 交换变量 $x$ 和 $y$ 的值。

我们的伪代码使用了一些可能不熟悉的运算符。与数学中的标准做法一样，（普通）除法用 $/$ 运算符表示。在许多情况下，我们希望进行整数除法，这时我们使用 $\bdiv$ 运算符，因此 $a \bdiv b = \lfloor a/b\rfloor$ 是 $a/b$ 的整数部分。例如，$3/2=1.5$ 但 $3 \bdiv 2 = 1$。偶尔，我们也会使用 $\bmod$ 运算符来获取整数除法的余数，但这将在使用时定义。在本书后面，我们可能会使用一些位运算符，包括左移（$\ll$）、右移（$\gg$）、按位与（$\wedge$）和按位异或（$\oplus$）。

**练习 1.1** 本练习旨在帮助读者熟悉如何为正确的问题选择正确的数据结构。如果实现的话，本练习的各部分应通过使用相关接口（Stack、Queue、Deque、USet或SSet）的实现来完成，该实现由编程语言提供。

通过逐行读取文本文件并对每行在适当的数据结构上执行操作来解决以下问题。你的实现应该足够快，即使包含一百万行的文件也能在几秒钟内处理完。

1. 一次读取一行输入，然后以相反顺序写出各行，使得最后一行输入最先打印，倒数第二行输入其次，依此类推。
2. 读取前50行输入，然后以相反顺序写出它们。读取接下来的50行，然后以相反顺序写出它们。重复此操作，直到没有更多行可读，此时任何剩余的行都应以相反顺序输出。
   换句话说，你的输出将从第50行开始，然后是第49行、第48行，依此类推直到第1行。随后是第100行，然后是第99行，依此类推直到第51行，以此类推。你的代码在任何时候都不应存储超过50行。
3. 一次读取一行输入。在读取前42行之后的任何时候，如果有某行是空白（即长度为0的字符串），则输出该行之前第42行的内容。例如，如果第242行是空白的，那么你的程序应输出第200行。此程序的实现应确保在任何时候都不存储超过43行输入。
4. 一次读取一行输入，如果该行不是之前某行输入的重复，则将其写入输出。特别注意，包含大量重复行的文件不应使用超过唯一行数所需的内存。
5. 一次读取一行输入，仅当之前已经读过此行时才将其写入输出。（最终结果是移除每行的第一次出现。）特别注意，包含大量重复行的文件不应使用超过唯一行数所需的内存。
6. 一次读取一行整个输入。然后按长度对所有行进行排序输出，最短的行在前。如果两行具有相同的长度，则使用通常的"排序顺序"来解决它们的顺序。重复的行应只打印一次。
7. 与上一题相同，但重复的行应按照它们在输入中出现的次数打印。
8. 一次读取一行整个输入，然后输出偶数编号的行（从第一行，行0开始），后跟奇数编号的行。
9. 一次读取一行整个输入，并在输出前随机排列各行。需要明确的是：你不应修改任何行的内容。相反，应打印相同集合的行，但以随机顺序。

**练习 1.2** 一个**Dyck词**（Dyck word）是由+1和-1组成的序列，其性质是序列的任何前缀的和都不为负。例如，$+1,-1,+1,-1$ 是一个Dyck词，但 $+1,-1,-1,+1$ 不是Dyck词，因为前缀 $+1-1-1<0$。描述Dyck词与Stack的 $\mathrm{push}(x)$ 和 $\mathrm{pop}()$ 操作之间的任何关系。
