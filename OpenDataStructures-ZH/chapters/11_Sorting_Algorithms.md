# 第11章 排序算法

本章讨论对 n 个元素进行排序的算法。在一本关于数据结构的书中讨论这个话题似乎有些奇怪，但这里包含它有几个充分的理由。最明显的理由是，这些排序算法中的两种（快速排序和堆排序）与我们之前研究过的两种数据结构（随机二叉搜索树和堆）密切相关。

本章的第一部分讨论仅使用比较进行排序的算法，并介绍三种运行时间为 O(n log n) 的算法。事实证明，这三种算法都是渐近最优的；任何仅使用比较的算法在最坏情况下甚至平均情况下都无法避免进行大约 n log n 次比较。

在继续之前，我们应该注意，前面章节中介绍的任何 SSet 或优先队列（priority queue）实现也可以用来获得 O(n log n) 时间的排序算法。例如，我们可以通过在一个 BinaryHeap 或 MeldableHeap 上执行 n 次 add(x) 操作，然后再执行 n 次 remove() 操作来对 n 个元素进行排序。或者，我们可以在任何二叉搜索树数据结构上执行 n 次 add(x) 操作，然后执行中序遍历（中序遍历，in-order traversal）（练习 6.8）来按排序顺序提取元素。然而，这两种情况下，我们都花费了大量开销来构建一个从未被充分利用的结构。排序是一个非常重要的问题，因此有必要开发尽可能快速、简单和节省空间的直接方法。

本章的第二部分表明，如果我们允许比较之外的其他操作，那么情况就完全不同了。事实上，通过使用数组索引，可以在 O(c n) 时间内对范围 {0, ..., n^c-1} 内的一组 n 个整数进行排序。

## 11.1 基于比较的排序（Comparison-Based Sorting）

在本节中，我们介绍三种排序算法：归并排序（merge-sort）、快速排序（quicksort）和堆排序（heap-sort）。每种算法都接收一个输入数组 a，并在 O(n log n)（期望）时间内将 a 的元素按非递减顺序排序。这些算法都是基于比较的（comparison-based）。这些算法不关心被排序的数据是什么类型；它们对数据执行的唯一操作是使用 compare(a, b) 方法进行比较。回顾第 1.2.4 节，compare(a, b) 在 a < b 时返回负值，在 a > b 时返回正值，在 a = b 时返回零。

### 11.1.1 归并排序（Merge-Sort）

归并排序（merge-sort）算法是递归分治（divide and conquer）的经典例子：如果 a 的长度最多为 1，那么 a 已经排好序，所以我们什么也不做。否则，我们将 a 分成两半，a0 = a[0], ..., a[n/2-1] 和 a1 = a[n/2], ..., a[n-1]。我们递归地对 a0 和 a1 进行排序，然后合并（现在已排好序的）a0 和 a1，得到完全排好序的数组 a：

```python
def merge_sort(a):
    if len(a) <= 1:
        return a
    m = len(a) // 2
    a0 = merge_sort(a[:m])
    a1 = merge_sort(a[m:])
    merge(a0, a1, a)
    return a
```

一个示例如图 11.1 所示。

**图 11.1:** merge_sort(a, c) 的执行过程

与排序相比，合并两个已排序的数组 a0 和 a1 相当容易。我们一次一个地向 a 中添加元素。如果 a0 或 a1 为空，那么我们从另一个（非空）数组中添加下一个元素。否则，我们取 a0 中下一个元素和 a1 中下一个元素中的最小值，并将其添加到 a 中：

```python
def merge(a0, a1, a):
    i0 = i1 = 0
    for i in range(len(a)):
        if i0 == len(a0):
            a[i] = a1[i1]
            i1 += 1
        elif i1 == len(a1):
            a[i] = a0[i0]
            i0 += 1
        elif a0[i0] <= a1[i1]:
            a[i] = a0[i0]
            i0 += 1
        else:
            a[i] = a1[i1]
            i1 += 1
```

注意，merge(a0, a1, a, c) 算法在 a0 或 a1 中元素用完之前最多执行 n-1 次比较。

要理解归并排序的运行时间，最容易的方法是从其递归树（recursion tree）的角度来思考。暂时假设 n 是 2 的幂，因此 n = 2^{log n}，且 log n 是整数。参考图 11.2。归并排序将排序 n 个元素的问题转化为两个排序 n/2 个元素的问题。这两个子问题又被转化为各两个问题，总共四个子问题，每个大小为 n/4。这四个子问题变成八个子问题，每个大小为 n/8，依此类推。在这个过程的底部，n/2 个大小为 2 的子问题被转化为 n 个大小为 1 的问题。对于每个大小为 n/2^i 的子问题，花费在合并和复制数据上的时间是 O(n/2^i)。因为有 2^i 个大小为 n/2^i 的子问题，所以花费在大小为 2^i 的问题上的总时间（不包括递归调用）为：

2^i × O(n/2^i) = O(n)

因此，归并排序所花费的总时间为：

∑_{i=0}^{log n} O(n) = O(n log n)

**图 11.2:** 归并排序的递归树

以下定理的证明基于上述分析，但需要更小心地处理 n 不是 2 的幂的情况。

**定理 11.1.** merge_sort(a) 算法运行时间为 O(n log n)，并且最多执行 n log n 次比较。

**证明：** 通过对 n 进行归纳证明。基本情况 n=1 是平凡的；当数组长度为 0 或 1 时，算法直接返回，不进行任何比较。

合并两个总长度为 n 的已排序列表最多需要 n-1 次比较。设 C(n) 表示 merge_sort(a, c) 在长度为 n 的数组 a 上执行的最大比较次数。如果 n 是偶数，那么我们对两个子问题应用归纳假设，得到：

C(n) ≤ n-1 + 2C(n/2)
     ≤ n-1 + 2((n/2)log(n/2))
     = n-1 + n log(n/2)
     = n-1 + n(log n - 1)
     < n log n

当 n 为奇数时，情况稍微复杂一些。对于这种情况，我们使用两个容易验证的不等式：

log(x+1) ≤ log(x) + 1    对所有 x ≥ 1     (11.1)

log(x+1/2) + log(x-1/2) ≤ 2 log(x)    对所有 x ≥ 1/2     (11.2)

不等式 (11.1) 来自于 log(x)+1 = log(2x) 的事实，而 (11.2) 则源于 log 是一个凹函数（concave function）。有了这些工具，对于奇数 n，我们有：

C(n) ≤ n-1 + C(⌈n/2⌉) + C(⌊n/2⌋)
     ≤ n-1 + ⌈n/2⌉ log⌈n/2⌉ + ⌊n/2⌋ log⌊n/2⌋
     = n-1 + (n/2+1/2) log(n/2+1/2) + (n/2-1/2) log(n/2-1/2)
     ≤ n-1 + n/2(log(n/2+1/2) - log(n/2-1/2)) + 1/2(log(n/2+1/2) + log(n/2-1/2))
     ≤ n-1 + n/2 + n/2 log(n/2) + 1/2·2 log(n/2)
     < n + n log(n/2)
     = n + n(log n - 1)
     = n log n  ∎

### 11.1.2 快速排序（Quicksort）

快速排序（quicksort）算法是另一种经典的分治算法。与归并排序在解决两个子问题后进行合并不同，快速排序在前期完成所有工作。

快速排序的描述很简单：从 a 中随机选择一个基准（pivot）元素 x；将 a 分为小于 x 的元素集合、等于 x 的元素集合和大于 x 的元素集合；最后，递归地对这个分区中的第一和第三集合进行排序。示例如图 11.3 所示。

```python
def quick_sort(a):
    if len(a) <= 1:
        return a
    i = random.randint(0, len(a)-1)
    pivot = a[i]
    # partition
    left = [x for x in a if x < pivot]
    mid = [x for x in a if x == pivot]
    right = [x for x in a if x > pivot]
    return quick_sort(left) + mid + quick_sort(right)
```

所有这些都是在原地完成的，因此 quick_sort(a, i, n, c) 方法只对子数组 a[i], ..., a[i+n-1] 进行排序。最初，该方法以参数 quick_sort(a, 0, len(a), c) 被调用。

快速排序算法的核心是原地分区（in-place partitioning）算法。该算法在不使用任何额外空间的情况下，交换 a 中的元素并计算索引 p 和 q，使得：

a[i] { < x  (0 ≤ i ≤ p)
      = x  (p < i < q)
      > x  (q ≤ i ≤ n-1)

这个由代码中的 while 循环完成的分区工作，通过迭代地增加 p 和减少 q 同时维持第一和最后一个条件来实现。每一步，位置 j 处的元素要么被移到前面，要么留在原处，要么被移到后面。在前两种情况下，j 递增，而在最后一种情况下，j 不递增，因为位置 j 处的新元素尚未被处理。

快速排序与第 7.1 节中研究的随机二叉搜索树（random binary search tree）密切相关。事实上，如果快速排序的输入包含 n 个不同元素，那么快速排序的递归树就是一棵随机二叉搜索树。要理解这一点，回顾一下在构造随机二叉搜索树时，我们首先做的是选择一个随机元素 x 并将其作为树的根。之后，每个元素最终都会与 x 进行比较，较小的元素进入左子树，较大的元素进入右子树。

在快速排序中，我们选择一个随机元素 x 并立即将所有元素与 x 进行比较，将较小的元素放在数组的开头，较大的元素放在数组的末尾。然后快速排序递归地对数组的开头和结尾进行排序，而随机二叉搜索树则递归地将较小的元素插入根的左子树，较大的元素插入根的右子树。

上述随机二叉搜索树和快速排序之间的对应关系意味着我们可以将引理 7.1 转换为关于快速排序的陈述：

**引理 11.1.** 当快速排序被调用对包含整数 0, ..., n-1 的数组进行排序时，元素 i 与基准元素进行比较的期望次数最多为 H_{i+1} + H_{n-i}。

对调和数（harmonic numbers）进行一些求和，我们得到以下关于快速排序运行时间的定理：

**定理 11.2.** 当快速排序被调用对包含 n 个不同元素的数组进行排序时，期望比较次数最多为 2n ln n + O(n)。

**证明：** 设 T 是快速排序对 n 个不同元素进行排序时执行的比较次数。使用引理 11.1 和期望的线性性质（linearity of expectation），我们有：

E[T] = ∑_{i=0}^{n-1} (H_{i+1} + H_{n-i})
     = 2∑_{i=1}^{n} H_i
     ≤ 2∑_{i=1}^{n} H_n
     ≤ 2n ln n + O(n)  ∎

定理 11.3 描述了被排序元素全部不同的情况。当输入数组 a 包含重复元素时，快速排序的期望运行时间不会更差，甚至可能更好；每当一个重复元素 x 被选为基准时，x 的所有出现都会被分组在一起，并且不参与两个子问题中的任何一个。

**定理 11.3.** quick_sort(a, c) 方法期望运行时间为 O(n log n)，并且其期望比较次数最多为 2n ln n + O(n)。

### 11.1.3 堆排序（Heap-sort）

堆排序（heap-sort）算法是另一种原地（in-place）排序算法。堆排序使用第 10.1 节中讨论的二叉堆（binary heap）。回顾一下，BinaryHeap 数据结构使用单个数组来表示堆。堆排序算法将输入数组 a 转换为堆，然后重复提取最小值。

更具体地说，一个堆将 n 个元素存储在数组 a 的位置 a[0], ..., a[n-1] 中，最小值存储在根 a[0] 处。将 a 转换为 BinaryHeap 后，堆排序算法重复交换 a[0] 和 a[n-1]，递减 n，并调用 trickle_down(0)，使得 a[0], ..., a[n-2] 再次成为有效的堆表示。当这个过程结束时（因为 n=0），a 的元素按递减顺序存储，因此反转 a 以获得最终的排序顺序。图 11.4 显示了 heap_sort(a, c) 执行的示例。

**图 11.4:** heap_sort(a, c) 执行的快照。数组的阴影部分已经排好序。非阴影部分是一个 BinaryHeap。在下一次迭代中，元素 5 将被放置到数组位置 8。

```python
def heap_sort(a):
    # 构建堆（自底向上）
    for i in range(len(a)//2 - 1, -1, -1):
        trickle_down(a, len(a), i)
    # 重复提取最小元素
    for i in range(len(a)-1, 0, -1):
        a[0], a[i] = a[i], a[0]
        trickle_down(a, i, 0)
    a.reverse()
```

堆排序中的一个关键子程序是用于将未排序数组 a 转换为堆的构造器。通过重复调用 BinaryHeap 的 add(x) 方法，可以很容易地在 O(n log n) 时间内完成，但我们可以使用自底向上（bottom-up）算法做得更好。回顾一下，在二叉堆中，a[i] 的子节点存储在 a[2i+1] 和 a[2i+2] 处。这意味着 a[⌊n/2⌋], ..., a[n-1] 没有子节点。换句话说，a[⌊n/2⌋], ..., a[n-1] 中的每一个都是大小为 1 的子堆。现在，从后往前工作，我们可以对每个 i ∈ {⌊n/2⌋-1, ..., 0} 调用 trickle_down(i)。这是可行的，因为当我们在调用 trickle_down(i) 时，a[i] 的两个子节点各自是一个子堆的根，所以调用 trickle_down(i) 使 a[i] 成为其自己子堆的根。

这种自底向上策略的有趣之处在于它比调用 n 次 add(x) 更高效。要理解这一点，请注意，对于 n/2 个元素，我们根本不做任何工作，对于 n/4 个元素，我们在根为 a[i] 且高度为 1 的子堆上调用 trickle_down(i)，对于 n/8 个元素，我们在高度为 2 的子堆上调用 trickle_down(i)，依此类推。由于 trickle_down(i) 所做的工作与以 a[i] 为根的子堆的高度成正比，这意味着总工作量最多为：

∑_{i=1}^{log n} O((i-1)n/2^i) ≤ ∑_{i=1}^{∞} O(i n/2^i) = O(n) ∑_{i=1}^{∞} i/2^i = O(2n) = O(n)

倒数第二个等式成立，因为根据期望值的定义，∑_{i=1}^{∞} i/2^i 等于我们抛硬币直到第一次出现正面所需的期望次数，并应用引理 4.2。

以下定理描述了 heap_sort(a, c) 的性能：

**定理 11.4.** heap_sort(a, c) 方法运行时间为 O(n log n)，并且最多执行 2n log n + O(n) 次比较。

**证明：** 该算法分三步运行：(1) 将 a 转换为堆，(2) 重复从 a 中提取最小元素，以及 (3) 反转 a 中的元素。我们刚刚论证了步骤 1 需要 O(n) 时间和 O(n) 次比较。步骤 3 需要 O(n) 时间且不进行比较。步骤 2 执行 n 次对 trickle_down(0) 的调用。第 i 次这样的调用在大小为 n-i 的堆上操作，并执行最多 2 log(n-i) 次比较。对 i 求和得到：

∑_{i=0}^{n-1} 2 log(n-i) ≤ ∑_{i=0}^{n-1} 2 log n = 2n log n

将三个步骤中执行的比较次数相加即完成证明。∎

### 11.1.4 基于比较排序的下界（A Lower-Bound for Comparison-Based Sorting）

我们现在已经看到了三种基于比较的排序算法，它们都在 O(n log n) 时间内运行。到现在为止，我们应该想知道是否存在更快的算法。这个问题的简短答案是否定的。如果允许对 a 的元素进行的唯一操作是比较，那么没有任何算法可以避免进行大约 n log n 次比较。这并不难证明，但需要一点想象力。最终，它源于以下事实：

log(n!) = log n + log(n-1) + ... + log(1) = n log n - O(n)

以上的非正式论证意味着，对于任何基于比较的排序算法，必须至少有 n! 个不同的执行路径。由于一个算法只能根据比较的结果做出决定，因此其执行路径可以用一棵比较树（comparison tree）来表示。由于必须至少有 n! 个不同的叶子（代表 n! 种可能的排列），并且二叉树的高度 h 最多有 2^h 个叶子，因此我们必须有 2^h ≥ n!，因此 h ≥ log(n!) = n log n - O(n)。因此：

**定理 11.5.** 任何基于比较的排序算法在最坏情况下至少执行 n log n - O(n) 次比较。

## 11.2 计数排序和基数排序（Counting Sort and Radix Sort）

在本节中，我们研究两种非基于比较的排序算法。这些算法专门用于排序小整数，通过使用（部分）a 中的元素作为数组的索引，避开了定理 11.5 的下界。考虑如下形式的语句：

c[a[i]] = 1

该语句在常数时间内执行，但根据 a[i] 的值，可能有 c 的长度种不同的结果。这意味着执行这种语句的算法不能建模为二叉树。最终，这就是本节中的算法能够比基于比较的算法排序更快的原因。

### 11.2.1 计数排序（Counting Sort）

假设我们有一个输入数组 a，由 n 个整数组成，每个整数都在范围 0, ..., k-1 内。计数排序（counting-sort）算法使用一个辅助计数器数组 c 对 a 进行排序。它输出 a 的排序版本作为辅助数组 b。

计数排序背后的思想很简单：对于每个 i ∈ {0, ..., k-1}，计算 i 在 a 中出现的次数并存储在 c[i] 中。现在，排序后，输出将如下所示：c[0] 个 0，后跟 c[1] 个 1，后跟 c[2] 个 2，...，后跟 c[k-1] 个 k-1。完成此操作的代码非常巧妙，其执行过程如图 11.7 所示：

```python
def counting_sort(a, k):
    c = [0] * k
    for x in a:
        c[x] += 1
    for i in range(1, k):
        c[i] += c[i-1]
    b = [0] * len(a)
    for x in reversed(a):
        c[x] -= 1
        b[c[x]] = x
    return b
```

**图 11.7:** 计数排序在长度为 n=20、存储整数 0, ..., k-1=9 的数组上的操作。

这段代码中的第一个 for 循环设置每个计数器 c[i]，使其计算 i 在 a 中出现的次数。通过使用 a 的值作为索引，这些计数器可以在 O(n) 时间内用一个 for 循环计算完毕。此时，我们可以直接使用 c 来填充输出数组 b。然而，如果 a 的元素有关联数据，这就不起作用了。因此我们多花一点功夫将 a 的元素复制到 b 中。

下一个 for 循环需要 O(k) 时间，计算计数器的累加和，使得 c[i] 成为 a 中小于或等于 i 的元素个数。特别地，对于每个 i ∈ {0, ..., k-1}，输出数组 b 将有：

b[c[i-1]] = b[c[i-1]+1] = ... = b[c[i]-1] = i

最后，算法从后往前扫描 a，将其元素按顺序放入输出数组 b。扫描时，元素 a[i] = j 被放置在位置 b[c[j]-1] 处，并且 c[j] 的值递减。

**定理 11.7.** counting_sort(a, k) 方法可以在 O(n+k) 时间内对包含集合 {0, ..., k-1} 中 n 个整数的数组 a 进行排序。

计数排序算法具有一个很好的性质，即它是稳定的（stable）；它保持相等元素的相对顺序。如果两个元素 a[i] 和 a[j] 具有相同的值，且 i < j，那么 a[i] 将在 b 中出现在 a[j] 之前。这将在下一节中很有用。

### 11.2.2 基数排序（Radix-Sort）

当数组的长度 n 不比数组中出现的最大值 k-1 小很多时，计数排序对整数数组进行排序是非常高效的。我们现在要描述的基数排序（radix-sort）算法使用多趟计数排序，允许更大的最大值范围。

基数排序通过使用 w/d 趟计数排序，每次对 d 位进行排序，来对 w 位整数进行排序。更准确地说，基数排序首先按整数的最低 d 位进行排序，然后按次低 d 位进行排序，依此类推，直到最后一趟按最高 d 位进行排序。

```python
def radix_sort(a, d):
    for p in range(0, 32//d + 1):
        b = counting_sort_on_digits(a, d, p)
        a = b
    return a
```

（在这段代码中，表达式 (a[i] >> d·p) & (2^d - 1) 提取了 a[i] 的位 (p+1)d-1, ..., pd 所表示的整数。）该算法步骤的示例如图 11.8 所示。

**图 11.8:** 使用 4 趟对 2 位整数的计数排序来对 8 位整数进行基数排序。

这个非凡的算法之所以能正确排序，是因为计数排序是一种稳定的排序算法。如果 x < y 是 a 中的两个元素，并且 x 与 y 不同的最高有效位索引为 r，那么在 ⌊r/d⌋ 趟中，x 将被放置在 y 之前，并且后续趟次不会改变 x 和 y 的相对顺序。

基数排序执行 w/d 趟计数排序。每趟需要 O(n + 2^d) 时间。因此，基数排序的性能由以下定理给出：

**定理 11.8.** 对于任意整数 d > 0，radix_sort(a, k) 方法可以在 O((w/d)(n + 2^d)) 时间内对包含 n 个 w 位整数的数组 a 进行排序。

如果我们换一种思考方式，将数组元素的范围设为 {0, ..., n^c-1}，并取 d = ⌈log n⌉，我们得到定理 11.8 的以下版本：

**推论 11.1.** radix_sort(a, k) 方法可以在 O(c n) 时间内对包含范围 {0, ..., n^c-1} 内 n 个整数值的数组 a 进行排序。

## 11.3 讨论与练习（Discussion and Exercises）

排序是计算机科学中基本的算法问题，有着悠久的历史。Knuth [48] 将归并排序算法归功于 von Neumann（1945）。快速排序归功于 Hoare [39]。原始的堆排序算法归功于 Williams [76]，但这里介绍的版本（其中堆以自底向上的方式在 O(n) 时间内构建）归功于 Floyd [28]。基于比较排序的下界似乎是民间传说。下表总结了这些基于比较算法的性能：

| 算法 | 比较次数 | 额外项 | 类型 | 原地？ |
|------|---------|--------|------|--------|
| 归并排序 | n log n | | 最坏情况 | 否 |
| 快速排序 | 1.38 n log n | + O(n) | 期望 | 是 |
| 堆排序 | 2 n log n | + O(n) | 最坏情况 | 是 |

这些基于比较的算法各有优缺点。归并排序进行的比较最少，且不依赖随机化。不幸的是，它在合并阶段使用了一个辅助数组。分配这个数组可能代价高昂，并且在内存有限时是一个潜在的失败点。快速排序是一种原地（in-place）算法，在比较次数方面紧随其后，但它是随机化的，因此这个运行时间并不总是有保证的。堆排序进行的比较最多，但它是原地且确定性的。

有一种情况下归并排序是明显的赢家；那就是对链表进行排序时。在这种情况下，不需要辅助数组；两个已排序的链表可以通过指针操作很容易地合并成一个已排序的链表（见练习 11.2）。

这里描述的计数排序和基数排序算法归功于 Seward [66, Section 2.4.6]。然而，基数排序的变体自 1920 年代以来就已用于使用穿孔卡片排序机对穿孔卡片进行排序。这些机器可以根据卡片特定位置是否有孔，将一叠卡片分成两堆。对不同孔位置重复此过程，就实现了基数排序。

最后，我们注意到计数排序和基数排序也可以用于排序非负整数之外的其他类型的数字。计数排序的直接修改可以在 O(n + b - a) 时间内对任何区间 {a, ..., b} 内的整数进行排序。类似地，基数排序可以在 O(n (log_n (b-a))) 时间内对同一区间内的整数进行排序。最后，这两种算法也可以用于排序 IEEE 754 浮点格式的浮点数。这是因为 IEEE 格式被设计为允许通过比较两个浮点数的值（就好像它们是带符号幅度二进制表示中的整数一样）来比较它们 [2]。
