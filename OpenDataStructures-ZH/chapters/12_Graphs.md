# 第12章 图

在本章中，我们研究图的两种表示形式以及使用这些表示的基本算法。

从数学上讲，一个**（有向）图** *directed graph* 是一个对 $G=(V,E)$，其中 $V$ 是一组**顶点** *vertices*，$E$ 是一组有序的顶点对，称为**边** *edges*。一条边 $(i,j)$ 是从 $i$ 到 $j$ 的**有向边** *directed*；$i$ 称为边的**源点** *source*，$j$ 称为边的**目标点** *target*。图 $G$ 中的一条**路径** *path* 是一个顶点序列 $v_0,\ldots,v_k$，使得对于每个 $i\in\{1,\ldots,k\}$，边 $(v_{i-1},v_{i})$ 都在 $E$ 中。如果路径 $v_0,\ldots,v_k$ 还满足边 $(v_k,v_0)$ 也在 $E$ 中，那么它就是一个**环** *cycle*。如果一条路径（或环）的所有顶点都是唯一的，那么它是**简单** *simple* 的。如果存在从某个顶点 $v_i$ 到某个顶点 $v_j$ 的路径，那么我们说 $v_j$ 是从 $v_i$ **可达的** *reachable*。图 12.1 展示了一个图示例。

<div align="center"><strong>图 12.1:</strong> 一个有十二个顶点的图。顶点被绘制为带编号的圆圈，边被绘制为从源点指向目标点的有尖曲线。</div>

由于图能够建模如此多的现象，它们有着大量的应用。有许多明显的例子。计算机网络可以被建模为图，其中顶点对应计算机，边对应这些计算机之间的（有向）通信链路。城市街道可以被建模为图，其中顶点代表交叉路口，边代表连接连续交叉路口的街道。

不太明显的例子发生在我们意识到图可以建模集合内的任意成对关系时。例如，在大学环境中，我们可能有一个时间表**冲突图** *conflict graph*，其顶点代表大学提供的课程，其中边 $(i,j)$ 存在当且仅当至少有一个学生同时选修了课程 $i$ 和课程 $j$。因此，一条边表示课程 $i$ 的考试不应该与课程 $j$ 的考试安排在同一时间。

在本节中，我们将用 $n$ 表示 $G$ 的顶点数，用 $m$ 表示 $G$ 的边数。即 $n=|V|$ 且 $m=|E|$。此外，我们假设 $V=\{0,\ldots,n-1\}$。任何我们想要与 $V$ 元素关联的其他数据都可以存储在一个长度为 $n$ 的数组中。

对图执行的一些典型操作包括：

- $\mathrm{add\_edge}(i,j)$：向 $E$ 添加边 $(i,j)$。
- $\mathrm{remove\_edge}(i,j)$：从 $E$ 中删除边 $(i,j)$。
- $\mathrm{has\_edge}(i,j)$：检查边 $(i,j)\in E$ 是否存在。
- $\mathrm{out\_edges}(i)$：返回所有满足 $(i,j)\in E$ 的整数 $j$ 的列表。
- $\mathrm{in\_edges}(i)$：返回所有满足 $(j,i)\in E$ 的整数 $j$ 的列表。

注意，这些操作实现起来并不特别困难。例如，前三个操作可以直接使用 USet 实现，因此可以使用第 5 章讨论的哈希表在常数期望时间内实现。最后两个操作可以通过为每个顶点存储其邻接顶点列表，在常数时间内实现。

然而，不同的图应用对这些操作有不同的性能要求，理想情况下，我们可以使用满足所有应用需求的最简单实现。因此，我们讨论两大类图表示。

## 12.1 AdjacencyMatrix：用矩阵表示图

**邻接矩阵** *Adjacency matrix* 是一种通过 $n\times n$ 矩阵 $a$ 来表示具有 $n$ 个顶点的图 $G=(V,E)$ 的方式，其条目为布尔值。

```
class AdjacencyMatrix:
    def __init__(self, n):
        self.n = n
        self.a = [[False]*n for _ in range(n)]
```

矩阵条目 $a[i][j]$ 定义为：

$$
a[i][j] = \begin{cases}
\mathrm{true} & \text{如果 } (i,j)\in E \\
\mathrm{false} & \text{否则}
\end{cases}
$$

图 12.1 中图的邻接矩阵如图 12.2 所示。

在这种表示中，操作 $\mathrm{add\_edge}(i,j)$、$\mathrm{remove\_edge}(i,j)$ 和 $\mathrm{has\_edge}(i,j)$ 只涉及设置或读取矩阵条目 $a[i][j]$：

```
def add_edge(self, i, j):
    self.a[i][j] = True

def remove_edge(self, i, j):
    self.a[i][j] = False

def has_edge(self, i, j):
    return self.a[i][j]
```

这些操作显然每次操作需要常数时间。

<div align="center"><strong>图 12.2:</strong> 一个图及其邻接矩阵。</div>

邻接矩阵表现不佳的地方在于 $\mathrm{out\_edges}(i)$ 和 $\mathrm{in\_edges}(i)$ 操作。为了实现这些操作，我们必须扫描 $a$ 的相应行或列中的所有 $n$ 个条目，并收集所有满足 $a[i][j]$ 或 $a[j][i]$ 为 true 的索引 $j$。这些操作显然每次操作需要 $O(n)$ 时间。

邻接矩阵表示的另一个缺点是它很大。它存储一个 $n\times n$ 的布尔矩阵，因此至少需要 $n^2$ 位内存。这里的实现使用了一个 `bool` 值矩阵，因此实际上需要 $O(n^2)$ 字节的内存。一个更精细的实现，将 $w$ 个布尔值打包到每个内存字中，可以将空间使用减少到 $O(n^2/w)$ 个字的内存。

> **定理 12.1.** *AdjacencyMatrix 数据结构实现了 Graph 接口。一个 AdjacencyMatrix 支持以下操作：*
> - *$\mathrm{add\_edge}(i,j)$、$\mathrm{remove\_edge}(i,j)$ 和 $\mathrm{has\_edge}(i,j)$，每次操作常数时间；*
> - *$\mathrm{in\_edges}(i)$ 和 $\mathrm{out\_edges}(i)$，每次操作 $O(n)$ 时间。*
> *AdjacencyMatrix 使用的空间为 $O(n^2)$。*

尽管其内存需求高且 $\mathrm{in\_edges}(i)$ 和 $\mathrm{out\_edges}(i)$ 操作性能差，AdjacencyMatrix 在某些应用中仍然有用。特别是，当图 $G$ 是**稠密的** *dense*，即它有接近 $n^2$ 条边时，$n^2$ 的内存使用可能是可以接受的。

AdjacencyMatrix 数据结构也常被使用，因为矩阵 $a$ 上的代数运算可以用来高效计算图 $G$ 的性质。这是一个算法课程的主题，但我们在此指出一个这样的性质：如果将 $a$ 的条目视为整数（$\mathrm{true}$ 为 1，$\mathrm{false}$ 为 0）并使用矩阵乘法将 $a$ 与自身相乘，那么我们得到矩阵 $a^2$。回忆矩阵乘法的定义：

$$
a^2[i][j] = \sum_{k=0}^{n-1} a[i][k] \cdot a[k][j]
$$

就图 $G$ 而言，这个公式计算的是使得 $G$ 同时包含边 $(i,k)$ 和 $(k,j)$ 的顶点 $k$ 的数量。也就是说，它计数了从 $i$ 到 $j$（通过中间顶点 $k$）长度为 2 的路径数量。这一观察是仅使用 $O(\log n)$ 次矩阵乘法计算 $G$ 中所有顶点对之间最短路径的算法的基础。

## 12.2 AdjacencyLists：图作为列表的集合

**邻接表** *Adjacency list* 表示采用了一种更以顶点为中心的方法。有许多可能的邻接表实现。在本节中，我们介绍一个简单的实现。在本节末尾，我们讨论不同的可能性。在邻接表表示中，图 $G=(V,E)$ 被表示为一个列表数组 $adj$。列表 $adj[i]$ 包含了所有与顶点 $i$ 相邻的顶点列表。也就是说，它包含所有满足 $(i,j)\in E$ 的索引 $j$。

```
class AdjacencyLists:
    def __init__(self, n):
        self.n = n
        self.adj = [ArrayStack() for _ in range(n)]
```

（示例如图 12.3 所示。）在这个特定的实现中，我们将 $adj$ 中的每个列表表示为 `ArrayStack`，因为我们希望按位置进行常数时间访问。其他选项也是可能的。具体来说，我们可以将 $adj$ 实现为 `DLList`。

<div align="center"><strong>图 12.3:</strong> 一个图及其邻接表。</div>

$\mathrm{add\_edge}(i,j)$ 操作只是将值 $j$ 追加到列表 $adj[i]$ 中：

```
def add_edge(self, i, j):
    self.adj[i].append(j)
```

这需要常数时间。

$\mathrm{remove\_edge}(i,j)$ 操作搜索列表 $adj[i]$ 直到找到 $j$ 然后删除它：

```
def remove_edge(self, i, j):
    for k in range(len(self.adj[i])):
        if self.adj[i].get(k) == j:
            self.adj[i].remove(k)
            return
```

这需要 $O(\deg(i))$ 时间，其中 $\deg(i)$（$i$ 的**度** *degree*）计数 $E$ 中以 $i$ 为源点的边的数量。

$\mathrm{has\_edge}(i,j)$ 操作类似；它搜索列表 $adj[i]$ 直到找到 $j$（并返回 true），或到达列表末尾（并返回 false）：

```
def has_edge(self, i, j):
    for k in range(len(self.adj[i])):
        if self.adj[i].get(k) == j:
            return True
    return False
```

这也需要 $O(\deg(i))$ 时间。

$\mathrm{out\_edges}(i)$ 操作非常简单；它返回列表 $adj[i]$：

```
def out_edges(self, i):
    return self.adj[i]
```

$\mathrm{in\_edges}(i)$ 操作的工作量要大得多。它扫描每个顶点 $j$，检查边 $(i,j)$ 是否存在，如果存在则将 $j$ 添加到输出列表中：

```
def in_edges(self, i):
    out = ArrayStack()
    for j in range(self.n):
        if self.has_edge(j, i):
            out.append(j)
    return out
```

这个操作非常慢。它扫描每个顶点的邻接表，因此需要 $O(n + m)$ 时间。

以下定理总结了上述数据结构的性能：

> **定理 12.2.** *AdjacencyLists 数据结构实现了 Graph 接口。一个 AdjacencyLists 支持以下操作：*
> - *$\mathrm{add\_edge}(i,j)$ 每次操作常数时间；*
> - *$\mathrm{remove\_edge}(i,j)$ 和 $\mathrm{has\_edge}(i,j)$ 每次操作 $O(\deg(i))$ 时间；*
> - *$\mathrm{in\_edges}(i)$ 每次操作 $O(n + m)$ 时间。*
> *AdjacencyLists 使用的空间为 $O(n + m)$。*

如前所述，在将图实现为邻接表时有许多不同的选择。出现的一些问题包括：

- 应该使用什么类型的集合来存储 $adj$ 的每个元素？可以使用基于数组的列表、链表，甚至是哈希表。
- 是否应该存在第二个邻接表 $inadj$，为每个 $i$ 存储满足 $(j,i)\in E$ 的顶点 $j$ 的列表？这可以大大减少 $\mathrm{in\_edges}(i)$ 操作的运行时间，但在添加或删除边时需要稍多一些工作。
- $adj[i]$ 中边 $(i,j)$ 的条目是否应该通过引用链接到 $inadj[j]$ 中相应的条目？
- 边是否应该是一等对象，具有自己的关联数据？这样，$adj$ 将包含边的列表而不是顶点（整数）的列表。

这些问题大多数归结为实现的复杂性（和空间）与实现的性能特征之间的权衡。

## 12.3 图遍历

在本节中，我们介绍两种探索图的算法，从其中一个顶点 $i$ 开始，并找到从 $i$ 可达的所有顶点。这两种算法最适合使用邻接表表示的图。因此，在分析这些算法时，我们将假设底层表示是 AdjacencyLists。

### 12.3.1 广度优先搜索

**广度优先搜索** *breadth-first-search* 算法从顶点 $i$ 开始，首先访问 $i$ 的邻居，然后是 $i$ 的邻居的邻居，然后是 $i$ 的邻居的邻居的邻居，以此类推。

该算法是二叉树广度优先遍历算法（第 6.1.2 节）的推广，且非常相似；它使用一个队列 $q$，初始只包含 $i$。然后重复从 $q$ 中提取一个元素并将其邻居添加到 $q$ 中，前提是这些邻居以前从未在 $q$ 中出现过。图的广度优先搜索算法与树的算法之间的一个主要区别是，图的算法必须确保它不会将同一个顶点多次添加到 $q$ 中。它通过使用一个辅助布尔数组 $seen$ 来跟踪哪些顶点已经被发现。

```
def bfs(g, r):
    seen = [False] * g.n
    q = SLList()
    q.add(r)
    seen[r] = True
    while q.size() > 0:
        i = q.remove()
        for j in g.out_edges(i):
            if not seen[j]:
                q.add(j)
                seen[j] = True
```

在图 12.1 的图上运行 $\mathrm{bfs}(g,0)$ 的示例如图 12.4 所示。不同的执行顺序是可能的，取决于邻接表的排序；图 12.4 使用了图 12.3 中的邻接表。

<div align="center"><strong>图 12.4:</strong> 从节点 0 开始广度优先搜索的示例。节点被标记为它们被添加到 $q$ 的顺序。导致节点被添加到 $q$ 的边绘制为黑色，其他边绘制为灰色。</div>

分析 $\mathrm{bfs}(g,i)$ 例程的运行时间相当直接。使用 $seen$ 数组确保没有顶点被多次添加到 $q$ 中。每个顶点从 $q$ 中添加（以及随后移除）每个顶点需要常数时间，总计 $O(n)$ 时间。由于每个顶点最多被内循环处理一次，每个邻接表最多被处理一次，因此 $G$ 的每条边最多被处理一次。这个在内循环中完成的处理每次迭代需要常数时间，总计 $O(m)$ 时间。因此，整个算法运行时间为 $O(n + m)$ 时间。

以下定理总结了 $\mathrm{bfs}(g,r)$ 算法的性能。

> **定理 12.3.** *当给定一个使用 AdjacencyLists 数据结构实现的图 $g$ 作为输入时，$\mathrm{bfs}(g,r)$ 算法运行时间为 $O(n + m)$ 时间。*

广度优先遍历有一些非常特殊的性质。调用 $\mathrm{bfs}(g,r)$ 最终将入队（并最终出队）每个存在从 $r$ 到 $j$ 的有向路径的顶点 $j$。此外，距离 $r$ 为 0 的顶点（$r$ 本身）将比距离为 1 的顶点先进入 $q$，距离为 1 的顶点将比距离为 2 的顶点先进入 $q$，依此类推。因此，$\mathrm{bfs}(g,r)$ 方法按与 $r$ 距离递增的顺序访问顶点，且无法从 $r$ 到达的顶点根本不会被访问。

因此，广度优先搜索算法一个特别有用的应用是计算最短路径。为了计算从 $r$ 到每个其他顶点的最短路径，我们使用 $\mathrm{bfs}(g,r)$ 的一个变体，它使用一个长度为 $n$ 的辅助数组 $p$。当一个新的顶点 $j$ 被添加到 $q$ 时，我们设置 $p[j] \gets i$。这样，$p[j]$ 成为从 $r$ 到 $j$ 的最短路径上的倒数第二个节点。重复这个过程，通过取 $p[p[j]]$、$p[p[p[j]]]$ 等等，我们可以重建（反向的）从 $r$ 到 $j$ 的最短路径。

### 12.3.2 深度优先搜索

**深度优先搜索** *depth-first-search* 算法类似于遍历二叉树的标准算法；它首先完全探索一个子树，然后返回当前节点并探索另一个子树。另一种理解深度优先搜索的方式是说它类似于广度优先搜索，但它使用栈而不是队列。

在深度优先搜索算法的执行过程中，每个顶点 $i$ 被分配一个颜色 $c[i]$：如果我们从未见过该顶点则为白色 *white*，如果我们当前正在访问该顶点则为灰色 *grey*，如果我们完成了对该顶点的访问则为黑色 *black*。思考深度优先搜索最简单的方式是将其视为一个递归算法。它从访问 $r$ 开始。当访问一个顶点 $i$ 时，我们首先将 $i$ 标记为灰色。接下来，我们扫描 $i$ 的邻接表并递归地访问我们在该列表中找到的任何白色顶点。最后，我们完成了对 $i$ 的处理，因此将 $i$ 涂成黑色并返回。

```
def dfs(g, i, c):
    c[i] = "grey"
    for j in g.out_edges(i):
        if c[j] == "white":
            dfs(g, j, c)
    c[i] = "black"
```

该算法执行的一个示例如图 12.5 所示。

<div align="center"><strong>图 12.5:</strong> 从节点 0 开始深度优先搜索的示例。节点被标记为它们被处理的顺序。导致递归调用的边绘制为黑色，其他边绘制为灰色。</div>

虽然深度优先搜索最好被视为递归算法，但递归并不是实现它的最佳方式。实际上，上面给出的代码对于许多大型图会因为栈溢出而失败。另一种实现是用显式栈 $s$ 替换递归栈。以下实现正是这样做的：

```
def dfs2(g, r):
    c = ["white"] * g.n
    s = SLList()
    s.push(r)
    while s.size() > 0:
        i = s.pop()
        if c[i] == "white":
            c[i] = "grey"
            for j in g.out_edges(i):
                s.push(j)
```

在前面的代码中，当下一个顶点 $i$ 被处理时，$i$ 被涂成灰色，然后被其在栈上的相邻顶点替换。在下一次迭代中，这些顶点中的一个将被访问。

毫不奇怪，$\mathrm{dfs}(g,r)$ 和 $\mathrm{dfs2}(g,r)$ 的运行时间与 $\mathrm{bfs}(g,r)$ 相同：

> **定理 12.4.** *当给定一个使用 AdjacencyLists 数据结构实现的图 $g$ 作为输入时，$\mathrm{dfs}(g,r)$ 和 $\mathrm{dfs2}(g,r)$ 算法各运行 $O(n + m)$ 时间。*

与广度优先搜索算法一样，深度优先搜索的每次执行都关联着一个底层树。当一个节点 $i \neq r$ 从白色变为灰色时，这是因为在处理某个节点 $i'$ 时递归调用了 $\mathrm{dfs}(g,i,c)$。（在 $\mathrm{dfs2}(g,r)$ 算法的情况下，$i$ 是替换栈上 $i'$ 的节点之一。）如果我们将 $i'$ 视为 $i$ 的父节点，那么我们得到一棵以 $r$ 为根的树。在图 12.5 中，这棵树是从顶点 0 到顶点 11 的一条路径。

深度优先搜索算法的一个重要性质如下：假设当节点 $i$ 被涂成灰色时，存在一条从 $i$ 到某个其他节点 $j$ 的仅使用白色顶点的路径。那么 $j$ 将首先被涂成灰色，然后在 $i$ 被涂成黑色之前被涂成黑色。（这可以通过反证法证明，考虑从 $i$ 到 $j$ 的任何路径 $P$。）

这一性质的一个应用是检测环。参考图 12.6。考虑某个可以从 $r$ 到达的环 $C$。令 $i$ 是 $C$ 中第一个被涂成灰色的节点，并令 $j$ 是环 $C$ 中 $i$ 的前驱节点。那么，根据上述性质，$j$ 将被涂成灰色，并且当 $i$ 仍然是灰色时算法将考虑边 $(j,i)$。因此，算法可以得出结论，在深度优先搜索树中存在一条从 $i$ 到 $j$ 的路径 $P$，并且边 $(j,i)$ 存在。因此，$P$ 也是一个环。

<div align="center"><strong>图 12.6:</strong> 深度优先搜索算法可用于检测 $G$ 中的环。节点 $j$ 在 $i$ 仍然是灰色时被涂成灰色。这意味着在深度优先搜索树中存在一条从 $i$ 到 $j$ 的路径 $P$，而边 $(j,i)$ 意味着 $P$ 也是一个环。</div>

## 12.4 讨论与练习

深度优先搜索和广度优先搜索算法的运行时间在定理 12.3 和定理 12.4 中有所夸大。定义 $n_r$ 为 $G$ 中存在从 $r$ 到 $i$ 的路径的顶点 $i$ 的数量。定义 $m_r$ 以这些顶点为源点的边的数量。那么以下定理是对广度优先搜索和深度优先搜索算法运行时间的更精确陈述。（运行时间的这种更精确的陈述在练习中概述的这些算法的某些应用中很有用。）

> **定理 12.5.** *当给定一个使用 AdjacencyLists 数据结构实现的图 $g$ 作为输入时，$\mathrm{bfs}(g,r)$、$\mathrm{dfs}(g,r)$ 和 $\mathrm{dfs2}(g,r)$ 算法各运行 $O(n_r + m_r)$ 时间。*

广度优先搜索似乎是由 Moore [52] 和 Lee [49] 分别在迷宫探索和电路路由的背景下独立发现的。

图的邻接表表示由 Hopcroft 和 Tarjan [40] 提出，作为（当时更常见的）邻接矩阵表示的替代。这种表示以及深度优先搜索在著名的 Hopcroft-Tarjan 平面性测试算法中发挥了主要作用，该算法可以在 $O(n)$ 时间内确定一个图是否可以在平面上绘制，且使得没有一对边相互交叉 [41]。

在以下练习中，**无向图** *undirected graph* 是指对于每个 $i$ 和 $j$，边 $(i,j)$ 存在当且仅当边 $(j,i)$ 存在。
