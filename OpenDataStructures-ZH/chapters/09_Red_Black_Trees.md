# 第9章 红黑树

在本章中，我们介绍红黑树（red-black trees），这是一种高度为对数级别的二叉搜索树（binary search tree）。红黑树是最广泛使用的数据结构之一。它们作为主要的搜索结构出现在许多库的实现中，包括Java Collections Framework和多种C++ Standard Template Library的实现。它们也被用于Linux操作系统内核中。红黑树的流行有以下几个原因：

1. 存储了 n 个值的红黑树的高度至多为 2log n。
2. 红黑树上的 add(x) 和 remove(x) 操作在最坏情况下的运行时间为 O(log n)。
3. 在 add(x) 或 remove(x) 操作中，均摊的旋转（rotation）次数为常数。

前两个属性已经使红黑树超越了跳表（skiplist）、treap和scapegoat树。跳表和treap依赖于随机化，它们的 O(log n) 运行时间只是期望值。Scapegoat树的高度有保证，但 add(x) 和 remove(x) 仅在均摊意义下以 O(log n) 时间运行。第三个属性则是锦上添花。它告诉我们，添加或删除元素 x 所需的时间远小于查找 x 所需的时间。^[9.1]

然而，红黑树的优良性质是有代价的：实现的复杂性。将高度维持在 2log n 的界限并非易事。它需要对大量情况进行仔细分析。我们必须确保实现在每种情况下都做正确的事情。一个错误的旋转或颜色更改就会产生一个难以理解和追查的bug。

我们不会直接跳入红黑树的实现，而是首先提供一些相关数据结构——2-4树——的背景知识。这将让我们了解红黑树是如何被发现的，以及为什么能够有效地维护它们。

## 9.1 2-4树

一棵2-4树（2-4 tree）是具有以下性质的有根树：

**性质 9..1** (高度) 所有叶子具有相同的深度。

**性质 9..2** (度数) 每个内部节点有2、3或4个子节点。

图9.1展示了一棵2-4树的例子。

2-4树的性质意味着它们的高度是叶子数量的对数：

**引理 9..1** 一棵有 n 个叶子的2-4树的高度至多为 log n。

*证明*。内部节点子节点数量的下界为2，这意味着如果一棵2-4树的高度为 h，则它至少有 2^h 个叶子。换句话说，n ≥ 2^h。对该不等式两边取对数，得到 h ≤ log n。∎

### 9.1.1 添加叶子

向2-4树添加叶子很简单（见图9.2）。如果我们想将叶子 u 添加为倒数第二层某个节点 w 的子节点，只需将 u 设为 w 的子节点。这当然保持了高度性质，但可能违反度数性质：如果 w 在添加 u 之前有四个子节点，那么 w 现在就有五个子节点。在这种情况下，我们**分裂**（split）w 为两个节点 w 和 w'，分别拥有两个和三个子节点。但现在 w' 没有父节点，所以我们递归地将 w' 设为 w 的父节点的子节点。这又可能导致 w 的父节点有太多子节点，于是我们再分裂它。这个过程一直持续，直到我们到达一个子节点少于四个的节点，或者直到我们将根 r 分裂为 r 和 r' 两个节点。在后一种情况下，我们创建一个新根，以 r 和 r' 为其子节点。这同时增加了所有叶子的深度，从而保持了高度性质。

由于2-4树的高度永远不会超过 log n，添加叶子的过程至多经过 log n 步后完成。

### 9.1.2 移除叶子

从2-4树中移除叶子稍微复杂一些（见图9.3）。要从其父节点 w 中移除叶子 u，我们只需移除它。如果 w 在移除 u 之前只有两个子节点，那么 w 就只剩下一个子节点，违反了度数性质。

为了纠正这个问题，我们考察 w 的兄弟节点 w'。节点 w' 一定存在，因为 w 的父节点至少有两个子节点。如果 w' 有三个或四个子节点，那么我们从 w' 拿走一个子节点给 w。现在 w 有两个子节点，w' 有两个或三个子节点，我们就完成了。

另一方面，如果 w' 只有两个子节点，那么我们将 w 和 w' **合并**（merge）为一个有三个子节点的节点 w。接着我们递归地从 w' 的父节点中移除 w'。这个过程在以下情况结束：当我们到达节点 u，而 u 或其兄弟有超过两个子节点时，或者当我们到达根时。在后一种情况下，如果根只剩下一个子节点，我们就删除根，让其子节点成为新根。这同样同时降低了每个叶子的深度，从而保持了高度性质。

同样，由于树的高度永远不会超过 log n，移除叶子的过程至多经过 log n 步后完成。

## 9.2 RedBlackTree：模拟的2-4树

红黑树（red-black tree）是一种二叉搜索树，其中每个节点 u 都有一个**颜色**（colour），要么是**红色**（red），要么是**黑色**（black）。红色用值0表示，黑色用值1表示。

在红黑树上的任何操作之前和之后，以下两个性质都得到满足。每个性质既用红色和黑色定义，也用数值0和1定义。

**性质 9..3** (黑高) 从根到叶子的每条路径上，黑色节点的数量相同。（任何根到叶子路径上的颜色之和相同。）

**性质 9..4** (无红边) 没有两个红色节点是相邻的。（对于除根以外的任何节点 u，u.colour + u.parent.colour ≥ 1。）

注意，我们总是可以将红黑树的根 r 涂成黑色而不违反这两个性质，因此我们假设根是黑色的，更新红黑树的算法将保持这一点。另一个简化红黑树的技巧是将外部节点（由 nil 表示）视为黑色节点。这样，红黑树中的每个真实节点 u 都有恰好两个子节点，每个子节点都有明确定义的颜色。图9.4展示了一棵红黑树的例子。

### 9.2.1 红黑树与2-4树

起初，红黑树能被高效地更新以维护黑高和无红边性质，这似乎令人惊讶，甚至将这些视为有用的性质也显得不寻常。然而，红黑树的设计目的正是为了作为二叉搜索树来高效模拟2-4树。

参考图9.5。考虑任意一棵有 n 个节点的红黑树 T，执行以下变换：移除每个红色节点 u，并将 u 的两个子节点直接连接到 u 的（黑色）父节点。经过这个变换后，我们得到一棵只有黑色节点的树 T'。

T' 中的每个内部节点都有两个、三个或四个子节点：一开始就有两个黑色子节点的黑色节点，在变换后仍然有两个黑色子节点。一开始有一个红色子节点和一个黑色子节点的黑色节点，在变换后有三个子节点。一开始有两个红色子节点的黑色节点，在变换后有四个子节点。此外，黑高性质现在保证了 T' 中每条根到叶子的路径具有相同的长度。换句话说，T' 是一棵2-4树！

2-4树 T' 有 n+1 个叶子，对应红黑树的 n+1 个外部节点。因此，这棵树的高度至多为 log(n+1)。现在，2-4树中的每条根到叶子的路径都对应红黑树 T 中从根到外部节点的一条路径。这条路径上的第一个和最后一个节点是黑色的，并且每两个内部节点中至多有一个是红色的，所以这条路径至多有 log(n+1) 个黑色节点和至多 log(n+1)-1 个红色节点。因此，T 中从根到任意**内部**节点的最长路径至多为

2log(n+1) - 2 ≤ 2log n

对于任意 n ≥ 1 成立。这证明了红黑树最重要的性质：

**引理 9..2** 有 n 个节点的红黑树的高度至多为 2log n。

既然我们已经看到了2-4树和红黑树之间的关系，就不难相信我们可以在添加和移除元素时高效地维护红黑树。

我们已经看到，在BinarySearchTree中添加元素可以通过添加一个新叶子来完成。因此，为了在红黑树中实现 add(x)，我们需要一种方法来模拟在2-4树中分裂一个有五个子节点的节点。一个有五个子节点的2-4树节点由一个黑色节点表示，该节点有两个红色子节点，其中一个还有一个红色子节点。我们可以通过将该节点涂成红色、将其两个子节点涂成黑色来"分裂"这个节点。图9.6展示了一个例子。

类似地，实现 remove(x) 需要合并两个节点以及从兄弟节点借用子节点的方法。合并两个节点是分裂的逆操作（如图9.6所示），包括将两个（黑色）兄弟节点涂成红色，并将它们的（红色）父节点涂成黑色。从兄弟节点借用子节点是最复杂的过程，涉及旋转和重新着色节点。

当然，在此过程中，我们仍然必须维护无红边性质和黑高性质。虽然这可以做到已经不再令人惊讶，但如果我们试图直接用红黑树模拟2-4树，需要考虑大量的情况。在某种程度上，忽略底层的2-4树，直接致力于维护红黑树的性质会更为简单。

### 9.2.2 左倾红黑树

红黑树没有单一的定义。相反，存在一系列结构，它们都能在 add(x) 和 remove(x) 操作期间维护黑高和无红边性质。不同的结构以不同的方式实现这一点。在此，我们实现一个称为RedBlackTree的数据结构。这个结构实现了一种特定变体的红黑树，满足一个额外的性质：

**性质 9..5** (左倾) 对于任意节点 u，如果 u.left 是黑色的，那么 u.right 也是黑色的。

注意，图9.4中展示的红黑树不满足左倾性质；最右侧路径上红色节点的父节点违反了该性质。

维护左倾性质的原因在于，它减少了在 add(x) 和 remove(x) 操作期间更新树时遇到的情况数量。就2-4树而言，这意味着每棵2-4树都有唯一的表示：度数为2的节点变为一个黑色节点，带有两个黑色子节点。度数为3的节点变为一个黑色节点，其左子节点为红色，右子节点为黑色。度数为4的节点变为一个黑色节点，带有两个红色子节点。

在我们详细描述 add(x) 和 remove(x) 的实现之前，首先介绍这些方法使用的一些简单子程序，如图9.7所示。前两个子程序用于在保持黑高性质的同时操作颜色。`push_black(u)` 方法接受一个有两个红色子节点的黑色节点 u，并将 u 涂成红色，将其两个子节点涂成黑色。`pull_black(u)` 方法逆转此操作：

```
def push_black(u):
    u.colour -= 1
    u.left.colour += 1
    u.right.colour += 1

def pull_black(u):
    u.colour += 1
    u.left.colour -= 1
    u.right.colour -= 1
```

`flip_left(u)` 方法交换 u 和 u.right 的颜色，然后在 u 处执行左旋转。这个方法逆转了这两个节点的颜色以及它们的父子关系：

```
def flip_left(u):
    swap_colours(u, u.right)
    rotate_left(u)
```

`flip_left(u)` 操作在恢复违反左倾性质的节点 u 时特别有用（因为 u.left 是黑色而 u.right 是红色）。在这种特殊情况下，我们可以确信此操作同时保持了黑高和无红边性质。`flip_right(u)` 操作与 `flip_left(u)` 对称，只是左右角色互换：

```
def flip_right(u):
    swap_colours(u, u.left)
    rotate_right(u)
```

### 9.2.3 添加

要在RedBlackTree中实现 add(x)，我们执行标准的BinarySearchTree插入，添加一个新叶子 u，其 u.x = x 并设置 u.colour = red。注意，这不会改变任何节点的黑高，因此不违反黑高性质。然而，它可能违反左倾性质（如果 u 是其父节点的右子节点），也可能违反无红边性质（如果 u 的父节点是红色的）。为了恢复这些性质，我们调用 `add_fixup(u)` 方法。

```
def add(x):
    u = BinarySearchTree.add(x)
    if u is None:
        return False
    u.colour = red
    add_fixup(u)
    return True
```

如图9.8所示，`add_fixup(u)` 方法接受一个颜色为红色的节点 u，该节点可能违反无红边性质和/或左倾性质。下面的讨论如果不参考图9.8或在纸上重现它，可能无法理解。事实上，读者可能希望在继续之前先研究该图。

如果 u 是树的根，那么我们可以将 u 涂成黑色来恢复两个性质。如果 u 的兄弟节点也是红色的，那么 u 的父节点一定是黑色的，所以左倾和无红边性质都已满足。

否则，我们首先判断 u 的父节点 w 是否违反左倾性质，如果是，则执行 `flip_left(w)` 操作并设置 u = w。这使我们进入一个定义良好的状态：u 是其父节点 w 的左子节点，所以 w 现在满足左倾性质。剩下的就是确保 u 处的无红边性质。我们只需要担心 w 是红色的情况，因为否则 u 已经满足无红边性质。

既然我们还没有完成，u 是红色的，w 也是红色的。无红边性质（仅被 u 违反而不被 w 违反）意味着 u 的祖父节点 g 存在且为黑色。如果 g 的右子节点是红色的，那么左倾性质保证 g 的两个子节点都是红色的，调用 `push_black(g)` 使 g 变成红色、w 变成黑色。这恢复了 u 处的无红边性质，但可能导致 g 处违反该性质，因此整个过程以 u = g 重新开始。

如果 g 的右子节点是黑色的，那么调用 `flip_right(g)` 使 w 成为 g 的（黑色）父节点，并给 w 两个红色子节点 u 和 g。这确保了 u 满足无红边性质，g 满足左倾性质。在这种情况下我们可以停止。

```
def add_fixup(u):
    while u.colour == red:
        if u == root:
            u.colour = black
            return
        w = u.parent
        if w.left.colour == black and w.right.colour == red:
            flip_left(w)
            u = w
            w = u.parent
        if w.colour == black:
            return
        g = w.parent
        if g.right.colour == red:
            push_black(g)
            u = g
        else:
            flip_right(g)
            return
```

`add_fixup(u)` 方法每次迭代花费常数时间，每次迭代要么完成，要么将 u 向根方向移动。因此，`add_fixup(u)` 方法在 O(log n) 次迭代后、以 O(log n) 时间完成。

### 9.2.4 移除

RedBlackTree中的 remove(x) 操作是实现最复杂的，这对所有已知的红黑树变体来说都是如此。就像BinarySearchTree中的 remove(x) 操作一样，这个操作归结为找到一个只有一个子节点 u 的节点 w，然后通过让 w.parent 收养 u 来将 w 从树中拼接出去。

问题在于，如果 w 是黑色的，那么黑高性质将在 w.parent 处被违反。我们可以暂时通过将 w.colour 加到 u.colour 上来避免这个问题。当然，这引入了另外两个问题：(1) 如果 u 和 w 一开始都是黑色的，那么 u.colour + w.colour = 2（双黑），这是一个无效的颜色。如果 w 是红色的，那么它被一个黑色节点 u 替换，这可能违反 u.parent 处的左倾性质。这两个问题都可以通过调用 `remove_fixup(u)` 方法来解决。

```
def remove(x):
    u = BinarySearchTree.remove(x)
    if u is None:
        return False
    w = u.parent
    if w is None:
        root = u
        if u is not None:
            u.colour = black
    else:
        u.parent = w.parent
        splice(w)
        u.colour += w.colour
        if u.colour == 2:
            remove_fixup(u)
            if u.parent is not None and u.parent.colour == red and \
               u.parent.left is not None and u.parent.left.colour == black and \
               u.parent.right is not None and u.parent.right.colour == black:
                flip_left(u.parent)
    return True
```

`remove_fixup(u)` 方法接受一个颜色为黑色（1）或双黑（2）的节点 u。如果 u 是双黑的，那么 `remove_fixup(u)` 执行一系列旋转和重新着色操作，将双黑节点向上移动，直到可以被消除。在此过程中，节点 u 不断变化，直到过程结束时 u 指向已被改变的子树根。该子树的根可能改变了颜色。特别是，它可能从红色变为黑色，所以 `remove_fixup(u)` 方法最后检查 u 的父节点是否违反左倾性质，如果是则修复它。

```
def remove_fixup(u):
    while u.colour == 2:
        if u == root:
            u.colour = 1
            return
        w = u.parent
        if w.left.colour == 1 and w.right.colour == 1 and \
           w.left.left is not None and w.left.left.colour == 0:
            flip_left(w)
            u = w
        else if w.left.colour == 1 and w.right.colour == 1 and \
                w.right.left is not None and w.right.left.colour == 0:
            push_black(w)
            u = w
        else:
            pull_black(u)
            u = w.parent
    if u.parent is not None and u.parent.colour == red and \
       u.parent.left is not None and u.parent.left.colour == black and \
       u.parent.right is not None and u.parent.right.colour == black:
        flip_left(u.parent)
```

`remove_fixup(u)` 方法在图9.9中进行了说明。同样，下面的文本如果不参考图9.9将是困难的，甚至不可能理解。`remove_fixup(u)` 中循环的每次迭代根据四种情况之一处理双黑节点 u：

**情况0：** u 是根。这是最容易处理的情况。我们将 u 重新着色为黑色（1），然后完成。

**情况1：** u 的兄弟节点是红色的。在这种情况下，u 的父节点是黑色的，而 u 的兄弟节点有两个黑色子节点（一个可能为 nil）。我们对 u 的父节点执行 `flip_left` 或 `flip_right` 操作，从而进入情况2、3或4。

**情况2：** u 的兄弟节点是黑色的，并且 u 的兄弟节点有一个红色子节点，该子节点与 u 的方向相同（即，如果 u 是左子节点，则兄弟节点的左子节点为红色）。在这种情况下，可以通过一次旋转和重新着色来消除双黑节点。我们对 u 的父节点执行一次旋转，并适当重新着色。

**情况3：** u 的兄弟节点是黑色的，并且 u 的兄弟节点有一个红色子节点，该子节点与 u 的方向相反。在这种情况下，我们对 u 的兄弟节点执行一次旋转（使其方向与 u 相同），然后进入情况2。

**情况4：** u 的兄弟节点是黑色的，并且 u 的兄弟节点的两个子节点都是黑色的。在这种情况下，我们从 u 中取出一个黑色，从 u 的兄弟节点中取出一个黑色，并将它们传递给 u 的父节点。这减少了 u 的黑色计数（从2到1或从1到0），但增加了父节点的黑色计数。如果父节点原来是红色的，它就变成黑色，过程结束。如果父节点原来是黑色的，它就变成双黑，我们递归地处理它。

## 9.3 总结

以下定理总结了RedBlackTree数据结构的性能：

**定理 9..1** RedBlackTree 实现了 SSet 接口，并支持 add(x)、remove(x) 和 find(x) 操作，每次操作的最坏情况时间为 O(log n)。

上述定理未包含以下额外奖励：

**定理 9..2** 从空的RedBlackTree开始，任意 m 次 add(x) 和 remove(x) 操作序列在所有 `add_fixup(u)` 和 `remove_fixup(u)` 调用中总共花费 O(m) 时间。

我们仅勾画定理9.2的证明思路。通过将 `add_fixup(u)` 和 `remove_fixup(u)` 与在2-4树中添加或移除叶子的算法进行比较，我们可以确信这一性质是从2-4树继承而来的。特别地，如果我们能证明在2-4树中分裂、合并和借用的总时间为 O(m)，那么就推出了定理9.2。

对2-4树的这个定理的证明使用了均摊分析中的势能法（potential method）。^[9.2] 将2-4树中内部节点 u 的势能定义为：

```
Φ(u) = 1  if u has 2 children
       0  if u has 3 children
       3  if u has 4 children
```

而一棵2-4树的势能为其所有节点势能之和。当发生分裂时，是因为一个有四个子节点的节点变成两个节点，分别有两个和三个子节点。这意味着整体势能下降了 3-1-0 = 2。当发生合并时，两个原来有两个子节点的节点被替换为一个有三个子节点的节点。结果是势能下降了 2-0 = 2。因此，每次分裂或合并，势能减少2。

接下来注意，如果忽略节点的分裂和合并，只有常数个节点的子节点数量会因添加或移除叶子而改变。添加节点时，一个节点的子节点数量增加1，势能最多增加3。移除叶子时，一个节点的子节点数量减少1，势能最多增加1，并且两个节点可能参与借用操作，它们的总势能最多增加1。

总结一下，每次合并和分裂导致势能至少下降2。忽略合并和分裂，每次添加或移除导致势能最多上升3，且势能始终非负。因此，在初始为空的树上进行 m 次添加或移除操作所导致的分裂和合并次数最多为 3m/2。定理9.2是这个分析以及2-4树与红黑树之间对应关系的推论。

## 9.4 讨论与练习

红黑树最早由Guibas和Sedgewick [38] 提出。尽管其实现复杂性很高，它们仍出现在一些最常用的库和应用程序中。大多数算法和数据结构教科书都讨论某种变体的红黑树。

Andersson [6] 描述了一种左倾版本的平衡树，类似于红黑树，但附加了任何节点至多有一个红色子节点的约束。这意味着这些树模拟的是2-3树而不是2-4树。然而，它们比本章介绍的RedBlackTree结构要简单得多。

Sedgewick [64] 描述了两种版本的左倾红黑树。它们使用递归以及模拟2-4树中的自顶向下分裂和合并。这两种技术的结合使得代码特别简短和优雅。

一个相关的、更古老的数据结构是**AVL树**（AVL tree）[3]。AVL树是**高度平衡的**（height-balanced）：在每个节点 u 处，以 u.left 为根的子树和以 u.right 为根的子树的高度最多相差1。由此立即可得，如果 F(h) 是高度为 h 的树中叶子的最小数量，那么 F(h) 服从斐波那契递推：

F(h) = F(h-1) + F(h-2)

初始条件为 F(0)=1 和 F(1)=1。这意味着 F(h) 近似为 φ^h/√5，其中 φ=(1+√5)/2≈1.61803399 是**黄金比例**（golden ratio）。（更精确地说，|φ^h/√5 - F(h)| ≤ 1/2。）按照引理9.1证明中的论证方式，这意味着

h ≤ log_φ n ≈ 1.440420088 log n

因此AVL树比红黑树的高度更小。在 add(x) 和 remove(x) 操作期间，可以通过沿路径向上回溯到根，并在每个 u 的左子树和右子树高度相差2的节点处执行重新平衡操作来维护高度平衡。参见图9.10。

Andersson的红黑树变体、Sedgewick的红黑树变体以及AVL树都比这里定义的RedBlackTree结构更易于实现。不幸的是，它们都不能保证重新平衡的均摊时间为每次 O(1) 更新。特别地，对于这些结构没有与定理9.2对应的结论。
