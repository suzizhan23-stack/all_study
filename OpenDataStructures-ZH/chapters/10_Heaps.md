# 第10章 堆

在本章中，我们讨论两种极其有用的优先队列（priority Queue）数据结构的实现。这两种结构都是一种特殊类型的二叉树，称为**堆**（heap），意为"一堆杂乱的东西"。这与二叉搜索树（binary search tree）形成对比，后者可以被认为是一个高度有序的堆。

第一种堆实现使用数组来模拟完全二叉树（complete binary tree）。这种非常快速的实现是已知最快的排序算法之一——堆排序（heapsort）的基础（见第11.1.3节）。第二种实现基于更灵活的二叉树。它支持 `meld(h)` 操作，允许优先队列吸收第二个优先队列 `h` 中的元素。

## 10.1 BinaryHeap：隐式二叉树（BinaryHeap: An Implicit Binary Tree）

我们第一个（优先）队列的实现基于一项已有四百多年历史的技术。**Eytzinger方法**（Eytzinger's method）允许我们通过按广度优先顺序（breadth-first order）排列节点，将完全二叉树表示为数组（见第6.1.2节）。通过这种方式，根节点存储在位置0，根节点的左子节点存储在位置1，根节点的右子节点存储在位置2，根节点的左子节点的左子节点存储在位置3，以此类推。见图10.1。

**图 10.1:** Eytzinger方法将完全二叉树表示为数组。

如果我们将Eytzinger方法应用于一个足够大的树，一些模式就会显现出来。索引 `i` 处的节点的左子节点位于索引 `left(i) = 2i + 1`，索引 `i` 处的节点的右子节点位于索引 `right(i) = 2i + 2`。索引 `i` 处的节点的父节点位于索引 `parent(i) = (i - 1) / 2`。

```
left(i)  = 2i + 1
right(i) = 2i + 2
parent(i) = (i - 1) // 2
```

BinaryHeap 使用这种技术隐式表示一棵完全二叉树，其中元素是**堆序**（heap-ordered）的：存储在任何索引 `i` 处的值不小于存储在索引 `parent(i)` 处的值，根节点值（`i = 0`）除外。因此，优先队列中的最小值存储在位置0（根节点）。

在 BinaryHeap 中，`n` 个元素存储在数组 `a` 中：

```
initialize():
    a ← new array of length 1
    n ← 0
```

实现 `add(x)` 操作相当直接。与所有基于数组的结构一样，我们首先检查 `a` 是否已满（检查 `length(a) = n`），如果是，则扩展 `a`。接下来，我们将 `x` 放在位置 `a[n]` 并递增 `n`。此时，剩下的就是确保我们维护堆属性。我们通过反复将 `x` 与其父节点交换，直到 `x` 不再小于其父节点来实现。见图10.2。

```
add(x):
    if length(a) = n then
        resize()
    a[n] ← x
    n ← n + 1
    i ← n - 1
    while i > 0 and a[parent(i)] > a[i] do
        swap a[i] and a[parent(i)]
        i ← parent(i)
    return true
```

**图 10.2:** 将值6添加到 BinaryHeap 中。

实现 `remove()` 操作（从堆中移除最小值）稍微复杂一些。我们知道最小值在哪里（根节点），但我们需要在移除后替换它，并确保维护堆属性。

最简单的方法是用值 `a[n - 1]` 替换根节点，删除该值，并递减 `n`。不幸的是，新的根元素现在可能不是最小的元素，因此需要将其向下移动。我们通过反复将该元素与其两个子节点进行比较来实现。如果它是三个中最小的，则完成。否则，我们将该元素与其两个子节点中最小的交换，并继续。

```
remove():
    x ← a[0]
    n ← n - 1
    a[0] ← a[n]
    i ← 0
    while true do
        j ← -1
        if left(i) < n and a[left(i)] < a[i] then
            j ← left(i)
        if right(i) < n and a[right(i)] < a[j] then
            j ← right(i)
        if j = -1 then break
        swap a[i] and a[j]
        i ← j
    return x
```

**图 10.3:** 从 BinaryHeap 中移除最小值4。

与其他基于数组的结构一样，我们将忽略调用 `resize()` 所花费的时间，因为这些时间可以通过引理2.1中的摊还分析（amortization argument）来解释。`add(x)` 和 `remove()` 的运行时间取决于（隐式）二叉树的高度。幸运的是，这是一棵**完全**（complete）二叉树；除了最后一层，每一层都有最大可能的节点数。因此，如果这棵树的高度为 `h`，那么它至少有 `2^h` 个节点。换句话说：

```
n ≥ 2^h
```

对等式两边取对数得到：

```
h ≤ log n
```

因此，`add(x)` 和 `remove()` 操作都在 `O(log n)` 时间内运行。

### 10.1.1 小结

以下定理总结了 BinaryHeap 的性能：

**定理 10.1.** *BinaryHeap 实现了（优先）队列接口。忽略调用 `resize()` 的成本，BinaryHeap 支持 `add(x)` 和 `remove()` 操作，每次操作的时间为 `O(log n)`。此外，从一个空的 BinaryHeap 开始，任何包含 `m` 次 `add(x)` 和 `remove()` 操作序列中，所有调用 `resize()` 所花费的总时间为 `O(m)`。*

## 10.2 MeldableHeap：随机化可合并堆（MeldableHeap: A Randomized Meldable Heap）

在本节中，我们描述 MeldableHeap，这是一种优先队列实现，其底层结构也是一个堆序二叉树。然而，与 BinaryHeap 不同（其底层二叉树完全由元素数量决定），MeldableHeap 对其底层二叉树的形状没有任何限制。

MeldableHeap 中的 `add(x)` 和 `remove()` 操作是通过 `merge(h1, h2)` 操作实现的。此操作接受两个堆节点 `h1` 和 `h2` 并合并它们，返回一个堆节点，该节点是以 `h1` 为根的子树中包含的所有元素和以 `h2` 为根的子树中包含的所有元素的堆的根节点。

`merge(h1, h2)` 操作的优点在于它可以递归定义。见图10.4。如果 `h1` 或 `h2` 为 `nil`，那么我们正在合并一个空集合，因此分别返回 `h2` 或 `h1`。否则，假设 `h1.x ≤ h2.x`，因为如果 `h1.x > h2.x`，我们可以交换 `h1` 和 `h2` 的角色。然后我们知道合并后的堆的根将包含 `h1.x`，我们可以递归地将 `h2` 与 `h1.left` 或 `h1.right` 合并，由我们决定。这就是随机化的用武之地，我们掷硬币来决定是将 `h2` 与 `h1.left` 还是 `h1.right` 合并：

```
merge(h1, h2):
    if h1 = nil then return h2
    if h2 = nil then return h1
    if h1.x > h2.x then swap h1 and h2
    if rand() < 0.5 then
        h1.left ← merge(h1.left, h2)
    else
        h1.right ← merge(h1.right, h2)
    return h1
```

**图 10.4:** 合并 `h1` 和 `h2` 是通过将 `h2` 与 `h1.left` 或 `h1.right` 之一合并来完成的。

在下一节中，我们将展示 `merge(h1, h2)` 在 `O(log n)` 期望时间内运行，其中 `n` 是 `h1` 和 `h2` 中元素的总数。

有了 `merge(h1, h2)` 操作，`add(x)` 操作就很简单了。我们创建一个包含 `x` 的新节点 `u`，然后将 `u` 与堆的根合并：

```
add(x):
    u ← new node containing x
    r ← merge(u, r)
    return true
```

这需要 `O(log (n + 1)) = O(log n)` 期望时间。

`remove()` 操作同样简单。我们要移除的节点是根节点，所以我们只需合并它的两个子节点，并将结果作为新的根节点：

```
remove():
    x ← r.x
    r ← merge(r.left, r.right)
    return x
```

同样，这需要 `O(log n)` 期望时间。

此外，MeldableHeap 可以在 `O(log n)` 期望时间内实现许多其他操作，包括：

- `remove(u)`：从堆中移除节点 `u`（及其键 `u.x`）。
- `absorb(h)`：将 MeldableHeap `h` 中的所有元素添加到此堆中，同时清空 `h`。

这些操作中的每一个都可以通过常数次 `merge(h1, h2)` 操作来实现，每次操作需要 `O(log n)` 期望时间。

### 10.2.1 分析 `merge(h1, h2)`

对 `merge(h1, h2)` 的分析基于对二叉树中随机游走（random walk）的分析。二叉树中的**随机游走**从树的根节点开始。在随机游走的每一步，掷一枚硬币，根据掷币结果，游走向当前节点的左子节点或右子节点前进。当游走掉出树（当前节点变为 `nil`）时，游走结束。

以下引理相当引人注目，因为它完全不依赖于二叉树的形状：

**引理 10.1.** *在具有 `n` 个节点的二叉树中，随机游走的期望长度最多为 `log(n + 1)`。*

*证明.* 通过对 `n` 进行归纳证明。基本情况：`n = 0` 时，游走长度为 `0 = log(n + 1)`。现在假设结果对所有非负整数 `n' < n` 成立。

设 `n1` 为根节点左子树的大小，那么 `n2 = n - n1 - 1` 为根节点右子树的大小。从根节点开始，游走前进一步，然后在大小为 `n1` 或 `n2` 的子树中继续。根据归纳假设，游走的期望长度为：

```
E[W] = 1 + (1/2) log(n1 + 1) + (1/2) log(n2 + 1)
```

由于 `n1` 和 `n2` 都小于 `n`。由于 `log` 是凹函数（concave function），当 `n1 = n2 = (n - 1)/2` 时，`E[W]` 最大。因此，随机游走期望步数为：

```
E[W] = 1 + (1/2) log(n1 + 1) + (1/2) log(n2 + 1)
     ≤ 1 + log((n - 1)/2 + 1)
     = 1 + log((n + 1)/2)
     = log(n + 1)
```

∎

我们简短地岔开话题，指出对于了解一些信息论（information theory）的读者，引理10.1的证明可以用熵（entropy）来表述。

*证明.* [引理10.1的信息论证明] 令 `di` 表示第 `i` 个外部节点（external node）的深度，并回忆具有 `n` 个节点的二叉树有 `n + 1` 个外部节点。随机游走到达第 `i` 个外部节点的概率恰好为 `pi = 1/2^di`，因此随机游走的期望长度为：

```
H = Σ pi * di = Σ pi * log(2^di) = Σ pi * log(1/pi)
```

这个等式的右边很容易被识别为 `n + 1` 个元素上的概率分布的熵。关于 `n + 1` 个元素上的分布熵的一个基本事实是它不超过 `log(n + 1)`，这证明了该引理。∎

有了这个关于随机游走的结果，我们现在可以很容易地证明 `merge(h1, h2)` 操作的运行时间是 `O(log n)`。

**引理 10.2.** *如果 `h1` 和 `h2` 分别是包含 `n1` 和 `n2` 个节点的两个堆的根，那么 `merge(h1, h2)` 的期望运行时间最多为 `O(log n)`，其中 `n = n1 + n2`。*

*证明.* 合并算法的每一步都是在以 `h1` 为根的堆或以 `h2` 为根的堆中进行一次随机游走。算法终止时，这两个随机游走中有一个掉出其对应的树（当 `h1 = nil` 或 `h2 = nil` 时）。因此，合并算法执行的期望步数最多为：

```
log(n1 + 1) + log(n2 + 1) ≤ 2 log n
```

∎

### 10.2.2 小结

以下定理总结了 MeldableHeap 的性能：

**定理 10.2.** *MeldableHeap 实现了（优先）队列接口。MeldableHeap 支持 `add(x)` 和 `remove()` 操作，每次操作的期望时间为 `O(log n)`。*

## 10.3 讨论与练习

将完全二叉树隐式表示为数组（或列表）的方法似乎最早由 Eytzinger 提出[27]。他在记载贵族家族的家谱书中使用了这种表示方法。此处描述的 BinaryHeap 数据结构最早由 Williams 引入[76]。

此处描述的随机化 MeldableHeap 数据结构似乎最早由 Gambin 和 Malinowski 提出[34]。存在其他可合并堆的实现，包括左偏堆（leftist heap）[16,48, 第5.3.2节]、二项堆（binomial heap）[73]、斐波那契堆（Fibonacci heap）[30]、配对堆（pairing heap）[29]和斜堆（skew heap）[70]，尽管这些都不如 MeldableHeap 结构简单。

上述一些结构还支持 `decrease_key(u, y)` 操作，该操作将节点 `u` 中存储的值减小为 `y`（前提条件是 `y ≤ u.x`）。在大多数前述结构中，可以通过移除节点 `u` 并添加 `y` 在 `O(log n)` 时间内支持此操作。然而，其中一些结构可以更高效地实现 `decrease_key(u, y)`。特别地，`decrease_key(u, y)` 在斐波那契堆中需要 `O(1)` 摊还时间，在配对堆的特殊版本中需要 `O(log log n)` 摊还时间[25]。这种更高效的 `decrease_key(u, y)` 操作在加速多种图算法中有应用，包括 Dijkstra 最短路径算法[30]。
